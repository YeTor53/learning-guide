# redirect r004-02：房间卡显示 8/8 却还能进 —— 按真实人数限制

## 1. 用户原话

> 还有房间人数在外面显示 8/8 你跟我说应该能进？毛病？按真实房间人数限制实现，抓紧项目，其他别管了，需求确认

## 2. 比对依据（三比，全部为代码/文档原文）

- **已批准口径（ADR-0012 修订）**：`D1 容量 = 在场（LiveKit 实测连接数）`、`D2 申请不校验容量`、`D3 批准不校验容量`、`D5 容量闸唯一在取票…外部查询失败时降级放行`、`D8 座位 = 在场；在册 = 本场已获准（不再占座、界面不单独呈现）`。
- **当前实现**（SHA 见提交史）：
  - 列表卡：`RoomCard.tsx` L66/L162 显示 `room.memberCount / room.capacity`（**在册活跃成员数 / 容量**），并据此画占用条 → 这就是你看到的「8 / 8」。
  - 交流页状态条：`RoomLivePage.tsx` L336 显示 `onlineIds.length / capacity 在房间`（**在场**口径）。
  - 准入：`services/rooms.py:issue_room_token` L443 用 `livekit.list_participant_identities` 数在场，`>= capacity` 才 409；该查询失败时降级为 `[]`（= 不拦）。
- **判定**：**两处显示用了两种口径，准入又是第三种状态的产物** —— 列表卡说「满」（在册 8/8），准入说「没满」（当时在场 0）→ 同一句话「8/8 还能进」，是**显示口径没跟上 ADR-0012 D1/D8 的修订**（属实现偏差 A）；而「查询失败降级放行」是 D5 明文写的（属**已批准设计**，要改成 fail-closed 就是设计变更，见 §5）。

## 3. 定性

- **结论：A（实现偏差）+ 一个必须走闸门的设计变更（L3）**
  - A 部分：列表卡按 D8 不该再用「在册/容量」讲话 → 按实现偏差修（走新补轮，因 r002 已合并打 tag，硬规矩 5）。
  - L3 部分：D5 的「外部查询失败降级放行」与你要求的「按真实房间人数限制」冲突 → 改为 **fail-closed**（真人数字校验失败就拒绝进场）；对外可见面变化（失败时的状态码与文案）→ 必须你批准。
- **载体**：r004 已 cp-7 收官、待合并；本单只登记，动手在新补轮 **r005-fix-capacity**。

## 4. 需求单口径（r005 草案要点）

- **目的**：房间「满没满」在**列表卡、交流页状态条、准入判定**三处**同一口径、同一数字**；容量以**真实在场人数**为准，校验失败**拒绝进场**而不是放行。
- **边界**：只碰容量口径与它带来的显示/接口/用例；**不做**排队实体、不做占座、不改房间生命周期（ADR-0012 其余条款不动）；顺手修同根因的「取票慢」（那次 LiveKit 查询就是 0.8~1.8s 的来源）。
- **验收（草案，编号稳定）**：
  - E1 列表卡显示「在场 N / 容量」且与准入一致；满员时卡片画满并给出「已满」态
  - E2 在场 = 容量 时第 N+1 人取票 → **409 `ROOM_FULL`**（保持现状）
  - E3 **校验失败即拒绝**：把 LiveKit 查询打桩成超时/报错 → 取票返回 **503 + 明确文案**（错误码待 Q2 定），并有 pytest 用例
  - E4 一致性用例：构造在场 N → 列表卡显示 N/容量、状态条显示 N/容量、第 N+1 人被拒（三处同数字）
  - E5 取票延迟：单次请求内 LiveKit 调用改为**短超时 + 缓存（TTL）**，实测取票中位数 < 500ms（现 1650ms）
  - E6 `pytest` 全绿 + `smoke.py` 全绿（新增容量与降级两组断言）
- **cp 计划（4 步）**：cp-1 口径与迁移（在场数缓存字段 + TTL + 常量）→ cp-2 后端（取票闸 fail-closed + 列表接口带在场数 + 短超时/缓存）→ cp-3 前端（列表卡与状态条统一「在场/容量」文案与满员态）→ cp-4 用例/冒烟/文档/取证（含打桩失败用例与延迟实测）。
- **文档产出清单**：`r005-fix-capacity.md`（需求单）、`rounds/r005-fix-capacity/{design,changes,review}.md`、模块页 `r001-rooms*.md`/`r002-livekit*.md` 的变更记录一行、ADR-0012 增补修订（D5 改 fail-closed、D8 落实显示口径）、实现页/功能页、开发者教学页补「容量口径」小节、AGENTS 验证命令不写死数字。
