你的要求：**变化时要保证动态效果，并且不反直觉**。本页回答「怎么设计」，几何规则见 `design.md`（`computeStageLayout` 是纯函数，只算位置），动画在组件层用 FLIP 实现。参数全部做成令牌，改一处即生效。

## 1. 会「变」的八种情况（逐条给对策）

| # | 变化 | 直觉期望 | 设计手法 | 反直觉陷阱（必须避免） |
| --- | --- | --- | --- | --- |
| C1 | 有人进入（发布视频） | 新来的**补空位**，别人轻微挪一下 | 新格 `fade + scale 0.92→1` 220ms；已有格用 FLIP 平移让位 | 所有格子瞬间重排一次「大洗牌」 |
| C2 | 有人离开 / 关摄像头 | **空位被填上**，不要留洞 | 先把离场格 `fade + scale→0.94` 180ms，**同时**邻居开始补位；动画结束后才从 DOM 摘除 | 离场格子「啪」地消失导致邻居瞬跳 |
| C3 | 焦点切换（手动指定） | 被指定者**长大**，上一个**缩回**，两者都别跳走 | 焦点格用 FLIP `translate + scale`，240ms；新旧焦点同时起步、同缓动 | 焦点格从左上「飞」到中间换位置（内容被裁切/闪烁） |
| C4 | 说话者自动焦点切换 | 会跟随，但**不要疯狂抽搐** | 说话检测 **debounce 800ms**；切换后 **冷却 3s**；**手动焦点锁定 10s 内不被自动顶掉**；只有 ≥2 人时才启用 | 两人轮流说话 → 画面每 300ms 跳一次（最反直觉） |
| C5 | 举手 / 放下手 | 只是**标记**，不动布局 | 纯视觉：3px 强调色呼吸边框 1.2s（不参与几何）；管理角标固定在该格右上，不随缩放跳动 | 举手导致重排/画面缩放（用户会以为点错了） |
| C6 | 屏幕共享开始/停止 | 共享**占主区**，人像让开；停止后**回到原来的样子** | 共享格进入：主区 240ms 扩张，人像格压缩到一行小格（同 FLIP）；停止：逆过程，且**恢复时焦点回落到共享前的那个人**（记住 `focusBeforeShare`） | 共享一停，焦点莫名变成别人（「我刚才指的人呢？」） |
| C7 | 窗口缩放 / 侧栏开合 | 平滑重排，不闪 | 尺寸变化 **debounce 150ms** 后重算几何；过渡仍走 FLIP；`resize` 期间不触发自动焦点切换 | 拖窗口时每帧重算 → 抖动、滚动条一闪一闪 |
| C8 | 人数从 1→2→…→8 | 越多人格子越小，但**相对顺序稳定** | 稳定排序：**本地 → 焦点 → 举手者 → 加入时间**；`bestGrid` 只在人数变化时重算列数 | 每次重排顺序乱换，找不到自己 |

## 2. 三条「不反直觉」硬规则

1. **几何用 transform，不用 width/height 动画**：宽高动画会触发重排、让视频内容抖动发虚；统一 FLIP（先读 `getBoundingClientRect`，反向 `transform` 到旧位置，再播放到新位置）。
2. **动画时长与人数、面积无关**：恒定 240ms（进入/离开 220/180ms）。人多时自动缩短会让节奏变得不可预期。
3. **变化期间不阻塞交互**：举手、静音、聊天在动画期间照常可用；动画只用 `pointer-events` 保护正在离场的格子（避免点到已离开的人）。

- 令牌（`frontend/src/styles/global.css` 的 `:root`，改这里即全局生效）：

| 令牌 | 默认 | 作用 |

| `--stage-move-ms` | 240ms | 布局位置/缩放过渡时长 |
| `--stage-ease` | `cubic-bezier(.22,1,.36,1)` | 统一缓动（快出慢入，像水波） |

| `--stage-gap` | 10px | 格子间距 |
| `--focus-weight` | 1.4 | 焦点格份量（实现为跨 2 格） |
| `--speaker-debounce-ms` | 800 | 说话者判定去抖 |
| `--speaker-cooldown-ms` | 3000 | 自动焦点切换冷却 |
| `--focus-hold-ms` | 10000 | 手动焦点保护期（期内不被自动顶掉） |

## 4. 降级与边界

| 情况 | 处理 |
| --- | --- |
| `prefers-reduced-motion: reduce` | 所有时长变量置 0：**瞬间到位**，但仍保持几何正确 |
| 浏览器不支持 FLIP 所需的 `getBoundingClientRect`（无） | 不存在，始终支持 |
| 动画中又发生变化 | 取消上一段动画（`element.getAnimations().forEach(a => a.cancel())`），从**当前可见位置**继续（避免回弹） |
| 同时进/退多人 | 一次布局计算 + 一次 FLIP（批量），不逐个动画 |
| 共享与焦点同时切换 | 以共享优先（ADR-0014），焦点变化排队到共享动画之后 120ms |

## 5. 怎么验（实测口径，cp-1/cp-5 用）

1. **终点一致性**：每次变化的 400ms 后，`getBoundingClientRect` 与 `computeStageLayout` 的理论矩形**误差 ≤ 1px**（脚本对比纯函数输出）。
2. **过渡确实发生**：变化瞬间 `el.getAnimations().length > 0` 且时长 = `--stage-move-ms`；reduced-motion 下为 0。
3. **无瞬移**：连续采样 10 帧，位置序列的**单帧最大位移 < 该格边长的 60%**（防止「一步跳到位」被当成动画）。
4. **不反直觉回归**：C4 场景（两人交替说话 30 秒）焦点切换次数 **≤ 3 次**；C6 场景（共享停止）焦点回到共享前那个人。
5. **铺满率**：变化结束后容器内格子总面积 / 可用面积 ≥ 0.90，且无横向滚动条（`scrollWidth <= clientWidth`）。
