# CR r010-02：转写换轨 —— 路径 B（本端上传）→ 路径 A/C（Agents 侧识别 + 前端回传落库）

## 触发
你 2026-09-20：「有免费档就行，只做最小程度演示，出设计方案」。此前你要求「测试一下A」，实测报告见 `spike-01-path-a.md`（**核心未核实项已兑现**：多用户注入房间、说话人可辨、渐进字幕、端到端中位 ~257ms / 官方 `transcript_delay 0.55s`、**不需要自备 STT key**）。据此把已批 design（路径 B）改为 **A/C 最小演示方案**。

## 决定与影响面（每项都标了"传播到哪"）

| # | 改什么 | 为什么 | 传播清单 |
| --- | --- | --- | --- |
| 1 | 转写识别移到 **Agents worker**（常驻第三进程，`inference.STT("deepgram/nova-3")`，免费档） | 实测：真实时（0.55s）、渐进字幕、归属天然、无需自备 key | design §9.1/§9.2；新增 `backend/agents/transcriber.py` + `requirements-agents.txt` + `agents.bat`；教学页（演示要先起 worker） |
| 2 | 我们的库由**前端回传 final 文本段**写入（接口从"传音频"改"传文本"） | 保住「HTTP 落库为唯一真相 + 可离线打桩 + 与既有架构一致」三条底线；复用 cp-1 的表 | design §9.3；`api/routers/transcripts.py`、`services/transcripts.py`、`repositories/transcripts.py`；**迁移 010**（新增 `external_id` 幂等键 + 放开 `segment_index` 非空） |
| 3 | 幂等键改 **LiveKit `segment.id`**（`(room_id, external_id)` 唯一） | 同一段可能被多端冗余上报；谁先到谁落，天然抗丢 | 迁移 010；用例（并发/重传） |
| 4 | 前端 `useTranscription` 从「MediaRecorder 分段上传」改为「监听 + 渲染 + 上报」 | 省掉 cp-3 大半工作量；渐进字幕由官方 `synchronizer` 免费提供 | design §9.4；`hooks/useTranscription.ts`（重写）、`ConversationPanel`、`TranscribeNotice` |
| 5 | **隐私口径变化**：转写发生在房间侧，音频会经 LiveKit Cloud 与 STT 供应商 | A 路径的固有性质，必须如实告知，不能沿用 B 的「只传我方后端」措辞 | 需求单 R6、告知条文案、教学页、ADR-0023、README |
| 6 | **"一键关转写"语义变化**：改由「关麦即不转写」承担 | A 路径下 STT 在 worker 侧，前端关不掉别人的识别；关自己麦克风＝无音频＝不转写（零额外代码） | 需求单 R1、design §9.2/§9.4、界面文案 |
| 7 | `.env`：`STT_MODE=agent|backend|off` + `STT_AGENT_NAME`；`STT_BASE_URL/KEY` 降级为「B 路径专用，可为空」 | 两条路径并存但不互相影响 | `.env.example`、`config.py`、docs README |
| 8 | 免费档护栏：STT 并发 ≤5 → 演示 **≤3 人、单场 ≤30 分钟**；worker 侧 `MAX_SESSIONS` 护栏 | 免费档 Inference STT 并发 5 条（见 spike §8.4） | design §9.2/§9.6；演示脚本；教学页 |

## 不改（沿用已批设计与既有实现）
- ADR-0022 的 **D2（协议用官方 `TranscriptionSegment`）**、**D3（只落最终稿）**、**D5（不保留音频）** 全部沿用；D1（路径 B）被本 CR 取代。
- 三源合一（`build_conversation` + `/conversation`）与纪要接转写：**不变**。
- `transcripts` 表、可见性规则、`smoke`/`pytest` 结构：不变（迁移 010 只加列与索引）。

## 三选一的取舍（本 CR 选 C）
| 选项 | 结论 |
| --- | --- |
| A 纯（识别在 worker，落库另定） | 需另定落库通道（后端订阅房间文本流），多一层 |
| **C 混合（本 CR 采纳）** | 前端回传 final 文本段 → 复用 cp-1 表与幂等；真相仍在我方 HTTP |
| B 原设计（本端上传音频） | **保留不激活**（`STT_MODE=backend` 时可用），作为将来无 worker 环境的降级档 |

## 前置与风险
- **前置**：① 你批本 CR ② 免档额度确认（控制台 Usage/Billing）
- **风险**：worker 掉线＝全场无转写（最小演示不做自愈，只做"前端如实显示未开启"）；免费档并发 5 与房容量 8 冲突（演示 ≤3 人规避）；`TranscriptionSegment.startTime/endTime` 真 STT 下是否有值待实测（影响 `duration_ms`/`started_at`，见 design §9.9）

## 结论
- 用户批复：**待批**；落地提交：—；ADR：**ADR-0023（proposed，与本 CR 同批）**
