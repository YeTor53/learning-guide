## 4. 需求单口径（一次确认后逐条改）

**A. 边界表（§2）**

- 「做」新增两条：
  1. **断线重连（连接层）**：网络抖动/短时断网后自动回到房间（`Reconnecting` / `Reconnected`），重连期间不退出房内页、显示「正在重连…」，恢复后自动续上；重连彻底失败才进入「连接已断开」+ 重连按钮。
  2. **设备状态保持（设备层）**：本人在重连前后保持麦克风/摄像头的开关状态（关着的回来还是关着），不弹权限询问。
- 「不做」新增一条：**断线重连后的业务状态恢复**（举手、焦点、屏幕共享、群聊未读）→ M3（能力未存在）/ M5 ①（原样保留登记）。

**B. Q5 口径补充（§3）**

- 追加一句：**重连不改库**。SDK 的全量重连对其他成员表现为「该成员离开又回来」，但成员身份以库为准 → 侧栏短暂显示离线再回在线，不产生 `inactive` 记录。

**C. 验收清单（§4）新增 3 条**

- [ ] **断网重连**：A 端断网 5~10 秒后恢复 → 自动回到房间（无需点按钮）、声画恢复；期间界面显示「正在重连…」且不离开房内页
- [ ] **断线原因（SDK 优先）**：被移出显示「你已被移出房间」、房间结束显示「房间已结束」——判定以 SDK 的断线原因为准（`PARTICIPANT_REMOVED` / `ROOM_DELETED`），取 Token 作为兜底
- [ ] **设备状态保持**：关掉摄像头后断网重连 → 回来仍是关摄像头状态；麦克风同理

**D. 前端实现（实现页 §7/§8）**

- `useRoomConnection`：新增 `Reconnecting` / `Reconnected` / `Disconnected(reason)` 三个事件处理；对外暴露连接状态机 `connecting \| connected \| reconnecting \| closed`。
- 新增 `useLocalDeviceState`：把摄像头/麦克风开关记在本地状态，`Reconnected` 后按记忆值重放（**具体重放方式与 SDK 是否会自行恢复发布需在 cp-r002-3 实测一次**，实测结果写回本页）。
- 房内页顶栏新增连接状态徽标（连接中 / 正在重连 / 已断开）。

**E. 功能层（功能页）**

- F-15 表新增两行：**重连中**（「正在重连…」不打断）、**重连成功**（徽标回到「已连接」，格子恢复）。
- 新增 **FQ-12**：同一账号在第二个窗口进入同一房间 → 按 SDK 行为是**后进把先进踢掉**（`DUPLICATE_IDENTITY`）；建议不禁止但给出提示「同一账号已在别处进入本房间，本窗口已断开」，并**修正 FQ-8 的旧口径**（见 §5 C-2）。

**F. 架构增量页**

- §6 验证矩阵加一行「断网重连（人工）：断网 5~10 秒后自动恢复」；§7 失败与边界加一行「重复身份（同账号双开）」。

**G. 教学页（预留，随 cp-r002-4）**
