# redirect r002-03：「已批准」这类原生弹窗掉价（记账 + r002 提示口径定死）

## 1. 用户原话 / 现象

> 「已批准的控制台消息太掉价了吧，记账」

指现状用浏览器**原生弹窗**做操作反馈与二次确认（`window.alert` / `window.confirm`）：样式由浏览器决定、与暗色编辑风完全割裂，观感确实掉价。

## 3. 定性

**C 后续工作（现有 8 处）+ r002 需补一条界面口径（提前做，按 L2 看待）**。

- 现有 8 处是 r001 已关闭轮次的产物，功能正确、只是形态掉价；你已明确「记账」→ 不修。
- **但 r002 会新增同类交互**（F-10 踢人二次确认、F-11 移交二次确认、「已移出 X，但实时断开可能延迟」提示、等候态各提示）——我在 r002 实现页 §7 只写了「二次确认弹窗」「提示」，**没写清形态**；不写死，实现时图省事就会再用 `window.confirm`，问题照旧。
- 因此本次一并请批：把 r002 的提示形态口径定死（站内 toast + 自绘 modal，禁浏览器原生弹窗）。不动接口 / 数据 / 验收项本身，按 L2 看待。
