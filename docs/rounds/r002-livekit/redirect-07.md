## 4. 需求单口径（r003 需求单草案要点）

- **目的**：房主在交流页有唯一、明确、二次确认的「结束房间」入口，不再出现「走不掉也结束不了」的死路。
- **做**：① 控制坞（`DeviceBar`）离场组：房主位置由禁用的「离开」改为**危险色「结束房间」**；非房主仍为「离开」，行为不变。② 点击弹**自绘**确认框（复用房内现有 `live-confirm` 模式，不用原生弹窗）：标题「结束这个房间？」，后果三条 —— 所有人被移出、需重新申请才能进；房间转为只读、历史仍可查；后续版本会生成一份讨论纪要。③ 确认后调 `POST /api/rooms/{id}/end` → 断开本地连接 → 回房间列表（卡片显示「已结束」）。④ `Esc` 取消确认，与现有退路一致。⑤ `connecting` / `reconnecting` 时禁用该按钮，与其它控制项一致。
- **不做**：抽屉里不加第二个入口；后端零改动；不做「结束后房主留在只读页」新视图；不动 8 处原生弹窗（`redirect-03` 仍未批）；不碰 M3 房内能力。
- **验收（可观察）**：a) 房主控制坞右侧为危险色「结束房间」且可点（截图）；b) 点击出确认框、`Esc` 可取消（截图）；c) 确认后列表页该卡片状态「已结束」且无动作；d) 另一浏览器同一房间 3 秒内断开并显示「房间已结束，仅可查看历史内容」；e) `npx tsc --noEmit` 全绿 + `npm run build` 成功；f) `pytest backend/tests -q` 仍 95 passed（后端零改动）；g) 演示教程第 9 步按新入口走通。
- **文档产出（覆盖矩阵）**：`r003` 需求单 + `docs/rounds/r003-end-room-entry/`（design / changes / review）；回填 r002 功能页 §4.2 按钮矩阵、§4.5 防呆条④、§4.9、§6 第 10 步；`r002-livekit.md` 变更记录一行；`docs/tutorials/r002-livekit-demo.md` 第 9 步 + `r002-livekit-setup.md` 第 11 行。
