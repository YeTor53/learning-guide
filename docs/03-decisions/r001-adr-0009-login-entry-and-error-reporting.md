## 背景

侧边栏落地后暴露出两个问题：

1. **登录入口位置**：ADR-0007 把「登录 / 注册」按钮放在侧边栏的个人信息区。用户 2026-09-17 指示改回第一版的位置——**顶栏右上角的无边框文字链接**；侧边栏左下角只放**个人信息**（不再是登录 / 注册）。原话：「登录和注册以无边框的文字形式显示在右上角（就像第一版），侧边栏左下角是个人信息，不是注册与登录」。
2. **错误呈现误导**：用户反馈首页「显示链接不到后端」。实测复现：未登录时点侧边栏「我的房间」会请求 `GET /api/rooms?mine=1`，后端按设计返回 `401 UNAUTHORIZED（请先登录）`；而列表页把**任何**查询失败都渲染成「房间列表加载失败，请检查后端是否已启动」，把「需要登录」误报成「后端挂了」。

## 决策

### 一、入口与位次（修订 ADR-0007 的对应条目）

| 位置 | 内容 |
| --- | --- |
| 顶栏右上角 | 未登录：`登录` / `注册` 两个**无边框文字链接**；已登录：显示名（点击进「我的房间」） |
| 侧边栏左下角 | **个人信息**（头像首字母、显示名、用户 id、邮箱、注册时间）+ `登出` + `收起侧边栏`；未登录时只显示「未登录 / 右上角登录后可见」占位 |
| 侧边栏上半区 | 主导航：返回主页 / 我的房间 / 创建房间 |

同时：侧边栏「我的房间」在未登录时**先跳登录页并带 `returnTo=/?mine=1`**，不再让请求打到后端去换一个 401。

### 二、错误呈现分流（新增规范，写入风格指南）

前端错误必须按来源分三类、给不同文案与出口，**禁止一句话兜底**：

| 类别 | 判定 | 文案与出口 |
| --- | --- | --- |
| 未登录 | `ApiError.status === 401` | 「请先登录」+ 说明（哪个功能需要登录）+「去登录」（带 `returnTo`）/「看全部房间」 |
| 业务错误 | 4xx 其它（如 404 `NOT_FOUND`、409 `ROOM_FULL`） | 直接展示服务端 `message`，并把可恢复动作列为按钮（重试 / 返回列表） |
| 连不上后端 | 网络异常 / 5xx | 明确写「连不上后端」+ 原样带出错误摘要 + 「重试」 |

## 理由

1. 登录 / 注册是**全局入口**，放顶栏右上角符合用户既有预期（第一版的肌肉记忆），也不占用侧边栏的信息位。
2. 侧边栏左下角是「我」的位置：个人信息常驻、与导航分离，视觉上更稳；登出紧跟其后符合操作习惯。
3. 401 是**预期内的状态**而不是故障：把它当成「后端挂了」会让人去排查服务，浪费时间。错误文案必须指向真正的下一步动作。

## 被否的替代方案

| 方案 | 为什么否掉 |
| --- | --- |
| 登录 / 注册继续放侧边栏（维持 ADR-0007 原样） | 用户明确要求改回右上角；且未登录时侧边栏的两颗按钮与「个人信息」标题语义冲突 |
| 两侧都放入口（侧边栏 + 顶栏） | 重复入口，且窄屏会出现两套登录按钮 |
| 未登录时隐藏「我的房间」入口 | 用户看不到能力边界；引导登录比隐藏更符合「未登录可浏览、需登录才操作」的既有口径 |
| 401 时静默回落到「全部房间」 | 用户不知道自己为什么没看到「我的房间」，属于隐性失败 |

- 文档：本 ADR 修订 ADR-0007 的「入口位置」与「个人信息位置」两处；账户功能页（区块顺序 / 按钮矩阵 / F-A-04 / F-A-05）与房间功能页（§4.1 草图）已同步；风格指南新增「导航与入口规范」「错误呈现规范」。
- 代码：`components/NavBar.tsx`（右上角文字入口）、`components/SideBar.tsx`（左下个人信息 + 未登录守卫）、`pages/RoomsPage.tsx` 与 `pages/RoomDetailPage.tsx`（错误三分流）、`styles/global.css`（`.link-plain`）。
- 未新增接口；后端 `pytest` 与 `smoke.py` 不受影响。
- 待办：其余页面（建房页、登录页、注册页）的错误呈现已符合三类规范，若后续新增页面按同一规范实现。
