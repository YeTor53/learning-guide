范围：首页（`/`，房间列表）的首屏信息优先级与窄屏/竖屏呈现。相关：功能页 §4.1（区块顺序）、`docs/rounds/r004-room-extras/changes.md` 的 cp-r004-3、roadmap §9 台账对应两行。

## 决策

1. **筛选条（工具栏）从 hero 之下上移到**顶栏正下方**（`RoomsPage` 的 DOM 顺序：toolbar → hero → 列表）。理由不是审美，而是**可发现性**：它是页面上唯一的操作入口组（状态/主题/只看我的/刷新/创建房间），任何窗口高度下都必须能立刻看到。
2. **竖屏（`orientation: portrait`）收敛 hero**：`--hero-min-h` 由 `min(78vh, 560px)` 收到 `min(58vh, 460px)`，插画透明度 0.5 → 0.42，统计行允许换行（`flex-wrap`）。让首屏在竖屏下也能露出列表的第一行。
3. **窄屏（≤900px）侧边栏改为一行横向条**：导航在左、个人信息在右（`flex-direction: row` + `justify-content: space-between`），并**忽略折叠状态**、**隐藏「收起侧边栏」按钮**。
4. 折叠状态只在宽屏（>900px）生效；穿越断点时**按展开渲染**（`collapsed && !narrowStrip`）。

## 理由

- **首屏是稀缺资源**：实测（2026-09-19，视口 1258×566）修改前 `.toolbar top = 639`，而首屏 566 高 → 需下滚约 73px 才看到筛选条；修改后 `top = 101`、`bottom = 146`，**完整落在首屏内**（roadmap §9 旧口径的门槛是 `toolbar.top ≤ 522`）。
- **压 hero 的算术不成立**（roadmap §9 已算过）：要让 toolbar 进 566 高的首屏需要 hero ≤ 385，而 hero 内容裸高 413 —— 靠压缩留白最多只能凑到 522 附近，属于「贴着边过」。把操作条提到 hero 之前是一次性、彻底且与窗口高度无关的解法。
- **hero 视觉不动**：标题、`think later/think together` 排版、插画、统计行全部保留，只是不再是页面第一块 —— 「第一印象」让位于「第一件能做的事」。
- **窄屏折叠状态穿越断点是真缺陷**：`collapsed` 为真时 `SideBar` 直接**不渲染** label（React 条件渲染），CSS 无法把它救回来 → 横向条只剩三个图标 + 居中内边距，看起来「样式出错」；同时横向条形态下折叠本身没有意义（没有可折叠的宽度）。因此按展开渲染 + 隐藏按钮，而不是加 CSS 硬撑。
- **窄屏压一行**省下一条 ~48px 的行高，直接换成首屏更多内容。

## 后果

- 功能页 §4.1 的区块顺序需同步：hero 之前是筛选条；本 ADR 生效后**以本 ADR 为准**（r001 功能页只追加一行指路，不改正文结论）。
- 新增一个前端 hook `hooks/useNarrowStrip.ts`（`max-width: 900px` 与 CSS 断点同阈值，单一事实源在注释里写明）；`SideBar` 新增 `hideToggle` 可选属性。
- 令牌/可调项：竖屏 hero 高度与插画透明度写在 `global.css` 的 `@media (orientation: portrait)` 块里，**改这两处即可调首屏节奏**。

## 备选与否决理由

| 备选 | 否决理由 |
| --- | --- |
| **B** 只做小视口压缩（`vh<700` 时把 `--hero-min-h` 归零、降字号、隐藏统计） | 是「贴着边过」：实测最多到 522 附近，窗口再矮一点又出界；且小屏观感变薄。 |
| **C** A + B 都做 | B 的收益被 A 覆盖（A 与高度无关），叠加只会让首屏更挤。 |
| **D** 不动，继续记账 | 用户 2026-09-19 明确选择「并进 r004」（Q7=2），不再挂账。 |
| 竖屏只压 hero、不改侧边栏 | 折叠按钮在横向条形态下依然会出现且点不出效果，缺陷留着。 |
