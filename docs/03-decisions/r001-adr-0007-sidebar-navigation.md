## 背景

r001 的功能页与实现页把导航定义为**顶部导航**（品牌 + 登录 / 注册 / 创建房间与登录态显示）。用户 2026-09-17 指示改成左侧边栏，用于放置「返回主页」「个人信息」等功能（原话：「加入侧边栏，用于放置返回主页，个人信息等功能」）。

## 决策

- 前端改为**左侧边栏 + 顶栏**的双层结构：侧边栏承载主导航（返回主页 / 我的房间 / 创建房间）、**个人信息区**（显示名、邮箱、注册时间、头像首字母）与会话操作（登录 / 注册 / 登出）；顶栏只留品牌与侧边栏折叠开关。
- 侧边栏可折叠（只隐藏文字、不隐藏可点区域）；窄屏（≤760px）折成横向条，不做抽屉浮层。
- 「我的房间」链接到 `/?mine=1`，筛选状态与 URL 同源（可直接分享/刷新保持）；侧边栏高亮由 URL 判定。
- 个人信息**不新增页面与接口**：数据源就是既有的 `GET /api/auth/me`（`UserVO` 已有显示名、邮箱、注册时间）；未登录时该区显示登录 / 注册入口与一句说明。

## 理由

1. 侧边栏是信息型应用更稳的导航骨架：房间列表 / 我的房间 / 创建房间属于同一层级的横向切换，竖排更好扫读，也给「个人信息」一个常驻位置。
2. 页面区块顺序不变（房间详情仍是头部 → 操作区 → 简介 → 成员 → 申请 → 消息），只换外壳，改动集中在布局组件。

## 被否的替代方案

| 方案 | 为什么否掉 |
| --- | --- |
| 保留顶部导航，只加「个人信息」下拉 | 用户明确要侧边栏；下拉在窄屏与移动端更难点，且不能承载「我的房间」等常驻入口 |
| 个人信息做成独立页面 `/profile` | 需要新路由 + 新页面，而数据与当前用户完全重合；本轮没有必要，留作 M5 的「个人资料编辑」候选 |
| 窄屏做抽屉（drawer）浮层 | 需要焦点陷阱与滚动锁定，成本高；本轮用横向条已可点、可读 |
