背景：r004 的「大焦点格 + 右侧缩略 rail 阶梯」被用户判为「焦点还是诡异」；用户要求均分铺满，并要求举手必须经管理确认才得焦点、协管内不能自己给自己焦点。ADR-0014（焦点/共享优先级）**继续有效**。

## 决定

### D1 布局：均分铺满 + 焦点跨 2 格（覆盖 ADR-0014 的布局部分）

- 所有人（已发布视频者）在可用区域内**等分铺满**：`bestGrid(n)` 选最接近目标宽高比的网格，`distribute(...)` 均分并消化像素余数。
- 有焦点时槽位数 = n + 1，**焦点格跨 2 个相邻槽位**（≈1.4 倍边长），其余人按序填充 → 不需要「rail 阶梯」这类特殊形态。
- 共享仍占主区（共享 > 焦点，沿用 ADR-0014 的优先级）。
- 好处：任意人数都不会出现「画面只占一半」；坏处：焦点不再是「大画面」，只是「明显更大的一格」——按用户口径接受。

### D2 焦点权限：房主直取、协管申请—他人批准

- **房主**：举手键位置即「取得焦点」，1 次请求直接生效（`set_focus`）。
- **协管**：举手键为「申请焦点」→ 建 `focus_requests(pending)` → **另一个非本人的管理身份**批准后生效；自己不能批自己（403 `SELF_APPROVAL`）。
- **参与者**：只能「举手」；由管理在其格子上点「给焦点」或「放下手」。
- 举手与焦点联动：给焦点时**同事务清掉该人举手**；焦点被清或焦点者离开时，其 pending 申请置 `cancelled`。

### D3 麦克风声波：用 LiveKit `audioLevel`，不引入 Web Audio

- 房内麦克风悬浮键展示音量环，数据来自 SDK 的 `audioLevel`（本地与远端均可），节流 100ms。
- 不用 `AnalyserNode`：省一套音频管线、避免与 LiveKit 抢占音频设备，精度对本场景足够。

## 影响

- 前端 `stageLayout.ts` 重写，r004 的 `--live-rail-*` 令牌与 `computeStageLayout` 旧签名废弃（模块页与测试同步更新）。
- 新增迁移 008（`focus_requests`）；`room_extras` 路由扩充 3 个端点 + 2 个错误码。
- 功能页新增 F-42（均分布局）/F-43（举手→焦点）/F-44（麦克风声波）。

## 备选与否决

| 备选 | 否决理由 |
| --- | --- |
| 保留 rail 阶梯，只调比例 | 用户明确要「均分铺满」，rail 的空隙问题还在 |
| 焦点格用绝对尺寸放大（不跨格） | 会与相邻格重叠或留下不规则空隙，难做铺满 |
| 协管与房主同权 | 用户明确要「另一个非本人批准」 |
| 音量用 Web Audio AnalyserNode | 与 SDK 音频管线重复，收益不足以抵消复杂度 |
