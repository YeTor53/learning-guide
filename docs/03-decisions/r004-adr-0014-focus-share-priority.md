范围：r004（M3）交流页焦点格。相关：功能页 F-16/F-21/F-22、`docs/rounds/r004-room-extras/design.md` §7、r002 §4.8（共享的布局预留）。

## 决策

| 优先级 | 条件 | 焦点格 |
| --- | --- | --- |
| 1 | 有人正在共享屏幕 | 共享画面（16:9 letterbox） |
| 2 | 房主/协管指定了焦点（`focus.subjectUserId` 非空且在册） | 该成员画面 |
| 3 | 有人在说话 | 说话者画面 |
| 4 | 兜底 | 自己 |

- 共享**压倒**手动焦点与说话者；手动焦点**压倒**说话者；说话者**压倒**自己（自己是最低优先，避免「自恋镜头」）。
- 取消共享/取消焦点后自动回落到下一级（纯派生，不新增状态）。

## 理由

- **共享是最强意图**：点共享的人是在说「请看这个材料」，把共享塞进缩格等于让它没法读；且 r002 §4.8 已按 16:9 letterbox 为它预留了焦点格；
- **手动焦点高于说话者**：房主的指定是**有意的调度**（例如「让 B 说完」），不该被一声咳嗽打断；
- **说话者高于自己**：r002 已定「单焦点 + 其余降权」的专注感，自己的画面放缩格不损失信息；
- **一个时刻只有一个焦点格**：与 r002 的「单焦点舞台」一致，不引入画中画（那会破坏专注感）。

## 后果

- `LiveStage` 需要 `pickFocusTile(...)` 这个纯函数（可单测、可肉眼验）；
- 演示脚本要多一条断言：「共享中有人说话，焦点格不变」（需求单 E12）；
- 若将来要「双焦点」（共享 + 说话者画中画），需要新 ADR 并重做布局 —— 本轮明确不做。

## 备选与否决理由

| 备选 | 否决理由 |
| --- | --- |
| 说话者 > 手动焦点 | 房主点名发言会被环境噪声打断，与「焦点」的语义相反 |
| 手动焦点 > 共享 | 共享画面进缩格后基本不可读，等于共享功能失效 |
| 说话者 > 共享 | 同 r002 的否决理由：共享是要一起看的内容，不能被说话者抢走 |
