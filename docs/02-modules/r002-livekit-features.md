实现（数据、接口、函数路径）以 **实现页** `docs/02-modules/r002-livekit.md` 为准；本轮范围与验收见需求单 `docs/00-requirements/r002-livekit-room.md`；

## 1. 使用者与角色

| 角色 | 怎么产生 | 房内可见范围 | 房内可做 |
| --- | --- | --- | --- |
| Host（房主） | 建房者；或被上一任 Host「移交房主」 | 全部 | 处理申请、踢任何人（除自己）、任命/取消协管、移交房主、结束房间 |
| Moderator（协管） | 被 Host「设为协管」 | 全部 | 处理申请、踢参与者（**不能**踢协管、不能踢 Host、不能踢自己） |
| Participant（参与者） | 申请获批 | 全部 | 开关自己的麦克风/摄像头、离开房间 |
| 已结束房间的任何人 | —— | 只读（成员、消息、纪要） | 无房内操作；「进入房间」按钮消失 |

## 3. 功能详述

### F-13 进入房间

- **入口**：房间详情页（`/rooms/:id`）的「进入房间」按钮；仅当「我是该房间的**活跃成员**」且房间 `active` 时出现。
- **前置**：已登录；申请已获批（未获批者停留在详情页，看到「等待房主批准」）。
- **行为**：点按钮 → 跳到 `/rooms/:id/live` → 页面自动取 Token 并连接（**不做 prejoin 弹窗**）→ 连接成功后看到视频格与自己的画面。
- **首次授权**：浏览器会弹「允许使用麦克风/摄像头」；拒绝或没有设备时，进房成功但自己的格子显示姓名首字头像块，页面顶部提示「未获得摄像头/麦克风权限，其他人听不到你说话」。
- **提示**：实时服务不可用 → 页面内错误卡片「实时服务暂时不可用，请稍后重试」+ 重试；房间已结束 → 「房间已结束，仅可查看历史内容」+ 返回详情。
- **验收点**：两个浏览器用**不同账号**进同一房间，能互相听到、看到；刷新页面自动重连。

### F-14 实时在场与本地设备控制

- **视频格**：参与者按人数自适应（1 人铺满 → 2 人并排 → 3 人以上网格）；格子显示画面、姓名、角色徽标、静音徽标；无摄像头时显示姓名首字头像块。
- **成员侧栏**：以**库成员列表**为骨架，LiveKit 在场者标「在线」，其余标「离线」（灰显，承接实现页 R-7 的建议值：显示离线成员，房主才能看到谁掉了）。
- **设备控制条**：麦克风开关、摄像头开关、「离开房间」；状态用图标 + 文字（不用颜色单独承载信息）。
- **连接状态徽标**（顶栏房间条）：已连接 / 正在重连… / 已断开；重连中不弹窗、不退出房内页。
- **设备状态保持**：麦克风/摄像头的开关在重连前后保持一致（关着的回来还是关着）。
- **规则**：静音/关摄像头只影响自己，不广播弹窗；他人格子上的对应徽标实时变化。
- **验收点**：A 关摄像头 → B 侧格子立即变为头像块；A 静音 → B 侧出现静音徽标。

### F-10 踢出成员

- **入口**：房内页成员行内「移出房间」（Host/Moderator）。
- **限制**：不能踢房主；协管不能踢协管（仅房主可）；不能踢自己（自己用「离开房间」）。
- **行为**：二次确认弹窗（「将 X 移出房间？对方会立即断开连接」）→ 确认后该成员：成员列表标记「被移出」；对方连接被**服务端强制断开**并显示「你已被移出房间」（非前端假踢）；被移出者可再次提交申请（承接 r001 FQ-3：立即允许）。
- **提示**：权限不足 → 「没有权限执行该操作」；实时服务调用失败 → 「已移出 X，但实时断开可能延迟」。
- **验收点**：踢人后对方页面**立刻**跳到「你已被移出房间」；刷新页面也回不来（Cloud 下旧 Token 已失效）；库内该成员 `status='inactive'`、`exit_reason='kicked'`。

### F-11 任命协管 / 移交房主

- **任命协管**：Host 在成员行选「设为协管 / 取消协管」；协管随即获得处理申请、踢人（除协管互踢）、（后续 M3 的）举手管理等能力；角色变化**立即**反映在双方页面的按钮可见性上。
- **移交房主**：Host 选「移交房主」→ 二次确认（「移交后你将变为协管，且不能再收回」）→ 双方角色互换：对方成为 Host，你变为**对方原来的角色**（参与者或协管）。
- **提示**：非 Host 看不到这两项（前端隐藏 + 服务端 403 双保险）。
- **验收点**：任命后对方能踢人、能批申请；移交后原 Host 的列表项变为「协管」，且其按钮集同步收窄。

### F-15 离开 / 被移出 / 房间结束的断开表现

| 来源 | 使用者看到 | 库内结果 |
| --- | --- | --- |
| 主动「离开房间」 | 回到房间详情页，提示「已离开房间」 | 成员 `inactive/self_leave` |
| 被 Host/协管移出 | 页面内卡片「你已被移出房间」+ 「返回房间列表」 | 成员 `inactive/kicked` |
| Host 结束房间 | 所有端卡片「房间已结束」+ 「查看讨论记录」 | 房间 `ended`；成员 `inactive/room_ended` |
| **重连中**（网络抖动/短时断网） | 徽标转「正在重连…」，画面可能短暂卡住但**不退出房内页**；其他端看到你短暂「离线」再回在线 | 无变化（重连不改库） |
| **重连成功** | 徽标回「已连接」，声画恢复，麦克风/摄像头保持原来的开关状态 | 无变化 |
| **同账号在第二个窗口进入同一房间** | 先进入的那个窗口被断开并提示「同一账号已在别处进入本房间」 | 无变化（两条连接不是两条成员记录） |
| 网络断开且重连失败 / 关标签页 | 「连接已断开」+ 重连按钮；**库内不变**（仍算成员，侧栏显示离线） | 无变化（判定留 M5） |
| 登录过期 | 「登录已失效，请重新登录」+ 去登录（带 `returnTo`） | 无变化 |

## 4. 页面级交互设计

### 4.1 房内页（`/rooms/:id/live`）布局

```
┌ 顶栏（沿用全局外壳：品牌 / 导航 / 登录态） ─────────────────────────────┐
├ 房间条：标题 · 主题标签 · 房间码 · 人数「N / 8」· 房间状态徽标 ─────────┤
├──────────────────────────────┬──────────────────────────────────────┤
│ 视频格区域（LiveStage）      │ 侧栏（RoomSidePanel）                │
│  自适应网格；每格：          │  · 成员（在线 / 离线，角色、退出原因）│
│  画面 / 头像块、姓名、       │  · 行内管理按钮（按角色显示）        │
│  角色徽标、静音徽标、        │  · 待处理申请（Host/协管，复用 r001）│
│  行内管理按钮                │  · 房间信息（主题/简介/创建时间）    │
├──────────────────────────────┴──────────────────────────────────────┤
│ 底部设备条：麦克风 · 摄像头 ·（M3 起：屏幕共享 / 举手 / 焦点 / 聊天）· 离开 │
└─────────────────────────────────────────────────────────────────────┘
```

- 视觉沿用 r001 的暗色编辑风与令牌（`docs/04-style/global-style.md`）；图标一律 Lucide，界面零 emoji。
- 空态：只有自己时，「等待其他人加入」；有人离线时侧栏对应行灰显。
- 错误态：不显示黑屏——先渲染错误卡片与原因文案（§3 F-13 的三种）。

### 4.2 按钮矩阵（房内页）

| 位置 | 按钮 | Host | Moderator | Participant | 条件 |
| --- | --- | --- | --- | --- | --- |
| 顶栏房间条 | 进入房间 | ——（已在房内） | —— | —— | —— |
| 成员行（他人） | 移出房间 | ✅ | ✅ | ❌ | 目标为活跃成员且非 Host；协管不可踢协管 |
| 成员行（他人） | 设为协管 / 取消协管 | ✅ | ❌ | ❌ | 目标为活跃成员 |
| 成员行（他人） | 移交房主 | ✅ | ❌ | ❌ | 目标为活跃成员 |
| 侧栏申请区块 | 批准 / 拒绝 | ✅ | ✅ | ❌（区块不可见） | 有 `pending` 申请且房间 `active` |
| 底部设备条 | 麦克风 / 摄像头 | ✅ | ✅ | ✅ | 恒显示，按设备状态切换图标与文案 |
| 底部设备条 | 离开房间 | ✅ | ✅ | ✅ | Host 需先移交或结束（承接 r001 FQ-2） |

- 前端隐藏 ≠ 安全边界：以上每一条都由服务端复核（实现页 §4）。
- 房间 `ended` 后：整页转为只读形态（按钮消失，保留成员与历史消息）。

### 4.3 四态（每屏必查）

| 态 | 表现 |
| --- | --- |
| 加载中 | 骨架屏（房间条 + 网格占位），不闪空白 |
| 空 | 只有自己在房内：「等待其他人加入」 |
| 错误 | 按错误码给具体原因（未获批 / 已结束 / 登录过期 / 实时服务不可用 / 连接断开） |
| 无权限 | 管理按钮不可见；若绕过前端直调 → 服务端 403，界面提示「没有权限执行该操作」 |

## 6. 端到端演示脚本（两个浏览器，人工）

准备：浏览器 A（`host@example.com`）、浏览器 B（`part@example.com`）；后端 dev 形态在 8000、前端在 `localhost:5173`（`localhost` 而非 `127.0.0.1`——浏览器只在安全上下文允许采麦克风/摄像头）。

1. A 建一间房（容量 3，便于演示满员），把房间码给 B。
2. B 打开房间页 → 提交申请；A 详情页出现「待处理申请 1」→ 批准。
3. B 详情页出现「进入房间」→ 点击 → 授权麦克风/摄像头 → 与 A **声画互通**（A 端能看到 B 的画面、听到声音）。
4. A 关摄像头、静音 → B 端看到头像块与静音徽标；反向再试一次。
5. A 在成员行把 B「设为协管」→ B 页面立刻出现「移出房间」按钮与待批申请区块。
6. 第三个浏览器 C（`mod@example.com`）申请 → B（协管）批准 → C 进房 → 现在 3/3 满员。
7. 第四个浏览器 D（新注册账号）申请 → 被拒并提示「房间已满（上限 3 人）」；A 侧同样无法批准（满员）。
8. A 把 B「移出房间」→ B 页面立刻出现「你已被移出房间」；B 刷新也回不来；A 侧成员列表该行标「被移出」。
9. B 再次提交申请 → A 批准 → B 重新进房（验证 FQ-3「立即允许」）。
10. A「结束房间」→ 所有端立刻断开并显示「房间已结束」；房间转为只读，成员与历史消息仍可查。
11. 回房间详情页确认：状态徽标「已结束」、成员退出原因（被移出 / 房间结束 / 主动离开）均可读。
12. （可选，验证 FQ-12）另开一间新房：两端进房后把其中一端的网络断掉 5~10 秒再恢复 → 徽标先「正在重连…」、随后自动回到「已连接」，声画恢复；期间库里不新增成员记录（`room_members` 行数不变）。

> 脚本执行状态：**未执行**（实现前）。执行后在本节下方追加「实测记录」并逐条勾选（需求单 §4 的人工验收项）。

## 7. 功能层待确认（FQ）

| 编号 | 事项 | 选项 | 本轮取值 | 影响 |
| --- | --- | --- | --- | --- |
| FQ-3 | 被移出者再申请 | 立即允许 / 设冷静期 | **立即允许**（承接 r001） | 演示脚本第 9 步 |

| FQ-11 | 被移出后是否保留在成员列表 | 保留并标「被移出」/ 直接移除 | **保留并标记**（承接 r001 FQ-5 的追溯口径） | 只读回访可查 |

| FQ-13 | 重连后业务状态（举手/焦点）是否恢复 | 本轮做 / 留后续 | **留 M3/M5 ①**（能力本身 M3 才有） | 演示脚本不写这一步 |
