## 1. 使用者与角色

| 角色 | 谁 | 在房间里想做什么 |
| --- | --- | --- |
| 访客（未登录） | 未注册/未登录的人 | 逛房间列表、看房间详情与历史消息，被引导登录后再操作 |
| 参与者 Participant | 被批准进入的人 | 进房讨论、看成员、看历史消息、离开房间 |
| 协管 Moderator | 房主任命的成员 | 参与者全部能力 + 处理加入申请、生成邀请、踢人 |
| 房主 Host | 建房的人 | 协管全部能力 + 结束房间、改角色、移交房主 |
| 系统 | 程序 | 房间结束时连带处理成员与未决申请；结束房间后按 M4 生成纪要 |

角色规则：一个用户在同一房间**同时只能有一个活跃身份**；`ended` 后所有角色都只剩「只读查看」。

## 3. 功能详述

### F-01 浏览房间列表

- **入口**：首页（默认展示 `active` 列表）。
- **界面元素**：状态筛选（进行中 / 已结束 / 全部）、主题筛选（4 个主题 + 全部）、排序（默认「进行中优先，其次按创建时间倒序」）、房间卡片、分页（每页 20 条）、「创建房间」主按钮。
- **卡片字段**：主题标签、标题、简介（截断 60 字）、房主显示名、状态徽标（进行中 / 讨论中 · N 人 / 已结束）、成员数（如 `3/8`）、待批申请数（仅当我是房主/协管时显示）、我的标识（我的角色徽标 / 「已申请」徽标）。
- **规则**：访客可见全部字段（不登录也能浏览）；`mine=1` 只看「我建的 / 我参与过的 / 我有待批申请的」房间（最后一项对应卡片上的「已申请」徽标）；列表不因房间结束而隐藏，改以「已结束」徽标区分。
- **状态**：
  - 加载中：卡片骨架（3 个占位卡）。
  - 空态（无房间）：「还没有房间，点击右上角创建第一个学习讨论室」+ 「创建房间」按钮。
  - 空态（筛选无结果）：「没有符合条件的房间，试试切换主题或状态筛选」+ 「清空筛选」。
  - 失败：区块内错误条 + 「重试」按钮，不整页报错。
- **验收点**：改库（新增/结束房间）后刷新列表，卡片数据随之变化；筛选与分页可复现。

### F-02 创建房间

- **入口**：列表页右上「创建房间」。
- **前置**：必须登录；未登录点击则跳转登录页，登录后回到建房页（`next=/rooms/new`）。
- **表单字段**：
  | 字段 | 必填 | 规则 | 提示 |
  | --- | --- | --- | --- |
  | 学习主题 | 是 | 单选：伊壁鸠鲁主义 / 数理生物学 / 德国史模拟 / 自定义（选自定义需填主题名） | 「主题决定房间的分类与展示标签」 |
  | 标题 | 是 | 1–80 字 | 超限即时提示「标题最多 80 字」 |
  | 简介 | 否 | ≤500 字 | 占位符：「想讨论什么？打算怎么进行？留几句话给加入的人」 |
- **提交行为**：按钮变「创建中…」并禁用；成功 → 跳转到新房间详情页并提示「房间已创建，你是房主」；失败 → 表单顶部错误条保留已填内容，不清空。
- **副作用**：创建者自动成为该房间「房主」成员（列表与详情立即体现）。
- **验收点**：未登录无法进入建房页；建成后列表出现该房间且房主是我。

### F-03 查看房间详情

- **区块顺序**：① 房间头部（主题徽标、标题、状态、房主、创建时间、房间码）② 我的操作区（按角色与状态变化的按钮）③ 简介 ④ 成员列表 ⑤ 待处理申请（Host/Moderator 可见）⑥ 最近消息（最近 20 条，只读）⑦ 纪要（房间结束后显示，见纪要功能页）。
- **成员列表字段**：显示名、角色徽标（房主 / 协管 / 成员）、加入时间；已退出成员（房间结束后）显示退出原因（主动离开 / 被移出 / 房间结束）。
- **最近消息**：时间为 `[HH:MM]`，格式 `发言人：内容`；无消息时显示「还没有人发言」。
- **刷新**：详情页每 5 秒自动刷新（可手动刷新）；M3 起房内实时状态改由 LiveKit 数据通道推送，不再轮询。
- **验收点**：区块顺序与字段齐全；改库后 5 秒内页面自动反映。

### F-04 提交加入申请（等候室）

- **入口**：详情页主按钮「申请加入」。
- **前置与拦截**（点击后按顺序判断，命中即停并给出对应提示）：
  1. 未登录 → 跳登录页（`next` 回到本房间）；
  2. 房间已结束 → 提示「该房间已结束，仅可查看历史内容」；
  3. 我已是活跃成员 → 提示「你已在房间中」并改为展示「进入房间」；
  4. 我已有待批申请 → 提示「你已提交过申请，请等待房主处理」；
  5. 房间人数已达上限 → 提示「房间已满（上限 8 人），请稍后再试或联系房主」。
- **申请表单**：可选留言（≤200 字），占位符「简单介绍一下你的兴趣方向（可选）」。
- **提交后**：详情页我的操作区变为「申请已提交，等待批准」状态徽标 + 「撤回申请」按钮（撤回即把申请置为已取消，可再次申请）。
- **验收点**：五种拦截各有对应提示；重复提交不产生第二条待批申请。

### F-05 查看与处理加入申请

- **可见性**：仅房主与协管可见该区块；其他人看不到区块本身（不是置灰）。
- **区块内容**：待处理数量徽标、每条申请的「申请人显示名 + 留言 + 提交时间」、行内「批准」「拒绝」两个按钮。
- **批准行为**：点击后按钮变「处理中…」；成功 → 该条移出待处理列表，成员列表实时多出该人并提示「已批准 David 加入」；若此时房间已满 → 提示「房间已满（上限 8 人），无法批准」并保留该申请为待批。
- **拒绝行为**：成功后该条移出列表并提示「已拒绝该申请」；申请人侧重新可提交申请（不设冷静期）。
- **空态**：「暂无待处理申请」。
- **历史查看**：已批准/已拒绝/已取消的申请在「查看全部申请」里可见（含决定时间与决定人），房间结束后仍可查看作为追溯。
- **验收点**：房间满员时批准被拒且申请仍在；批准后对方刷新即成为成员。

### F-08 离开房间

- **入口**：详情页「离开房间」（次要按钮，二次确认）。
- **规则**：房主不能直接离开 → 提示「房主不能直接离开，请先结束房间或移交房主」；非成员 → 提示「你不在该房间中」。
- **确认弹窗文案**：「离开后需要重新申请才能进入，确定离开吗？」→「离开」/「取消」。
- **离开后**：我的操作区回到「申请加入」；列表卡片上的我的角色徽标消失；成员列表不再显示我（房间结束后可看到我的退出原因）。

### F-09 结束房间

- **入口**：详情页「结束房间」（仅房主可见，危险操作样式）。
- **确认弹窗**：标题「结束这个房间？」；正文列后果：① 所有人被移出，需重新申请才能再进 ② 房间变为只读 ③ 系统会为这次讨论生成一份纪要；按钮「结束房间」/「取消」，其中「结束房间」为危险色。
- **结束后的房间表现**：状态徽标「已结束」；头部追加结束时间；操作区只保留「查看纪要」；成员列表显示全部历史成员与退出原因；最近消息仍可只读查看；申请区块只读（显示最终状态）。
- **连带效果对用户可见的部分**：其他在线成员收到「房间已结束」提示（M2 起随连接断开显示）；待处理申请显示为「已取消（房间结束）」。
- **验收点**：双浏览器验证——房主结束后，另一浏览器页面变为只读并提示已结束；列表徽标变「已结束」。

### F-12 只读回访已结束房间

- **入口**：列表切到「已结束」，或历史链接直接访问。
- **可做**：看简介、历史成员（含退出原因）、最近消息、纪要（若已生成）。
- **不可做**：申请加入、批准/拒绝、生成邀请、踢人、改角色、结束房间；这些按钮不显示，若通过接口直接调用则返回「该房间已结束」。

## 4. 页面级交互设计

### 4.1 房间列表页

```
┌ 学习讨论室 ──────────────────────── [创建房间] ┐
│ 状态: [进行中] 已结束  全部                     │
│ 主题: [全部] 伊壁鸠鲁主义 数理生物学 德国史模拟   │
├───────────────────────────────────────────────┤
│ ▢ 数理生物学 · 讨论中 · 3/8      [我的角色: 房主] │
│   用数学理解细胞的能量代谢                       │
│   房主 Ada · 10 分钟前                          │
│ ▢ 德国史模拟 · 已结束   [查看纪要]               │
└───────────────────────────────────────────────┘
```

### 4.2 建房页

单列表单（宽度受限居中），字段顺序：主题单选（含「自定义」+ 名称输入）→ 标题 → 简介（带字数计数 `0/500`）→ 底部「创建房间 / 取消」。校验在失焦与提交时各做一次。

### 4.3 房间详情页（区块与状态）

| 区块 | 访客（未登录） | 非成员已登录 | 已申请待批 | 成员 | 协管 | 房主 | 房间已结束 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 头部信息 | 显示 | 显示 | 显示 | 显示 | 显示 | 显示 | 显示 + 「已结束 · 结束时间」 |
| 主按钮 | 「登录后加入」 | 「申请加入」 | 「等待批准」+「撤回申请」 | 「进入房间」+「离开房间」 | 同成员 | 同成员 + 「结束房间」 | 「查看纪要」 |
| 待处理申请区块 | 隐藏 | 隐藏 | 隐藏 | 隐藏 | 显示 | 显示 | 只读（最终状态） |
| 成员列表 | 显示 | 显示 | 显示 | 显示 | 显示 | 显示 | 显示（含退出原因） |
| 最近消息 | 显示 | 显示 | 显示 | 显示 | 显示 | 显示 | 显示（只读） |
| 纪要区块 | 隐藏 | 隐藏 | 隐藏 | 结束后显示 | 结束后显示 | 结束后显示 | 显示 |

按钮禁用规则：任何操作进行中，相关按钮进入「处理中…」并禁用；被禁用的按钮必须以 `title`/副标题说明原因（如「房间已满」「仅房主可操作」），不允许无解释的灰按钮。

## 6. 端到端演示脚本（两个浏览器）

1. 浏览器 A（房主）：注册 `ada@example.com` → 登录 → 创建房间「用数学理解细胞的能量代谢」（主题：数理生物学）→ 详情页显示「房主」徽标。
2. 浏览器 B（成员）：注册 `david@example.com` → 登录 → 列表看到该房间（`1/8`）→ 打开详情 → 「申请加入」并填写留言。
3. 浏览器 A：详情页「待处理申请」出现 David 的申请 → 点「批准」→ 成员列表变为 2 人。
4. 浏览器 B：刷新详情页 → 状态变为「成员」，按钮变「进入房间」。
5. 浏览器 B：「离开房间」→ 确认 → 页面回到「申请加入」；浏览器 A 的成员列表回到 1 人。
6. 浏览器 B 再次申请，A 再次批准（验证重复申请与批准链路）。
7. 浏览器 A：「结束房间」→ 确认 → 页面变只读，状态徽标「已结束」。
8. 浏览器 B：刷新 → 显示「该房间已结束，仅可查看历史内容」，成员列表显示退出原因「房间结束」。
9. 浏览器 A：列表切「已结束」→ 出现该房间；详情页出现纪要区块（M4 起，内容见纪要功能页）。
