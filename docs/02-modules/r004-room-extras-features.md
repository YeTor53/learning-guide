本页是 r004（M3）的**功能事实**：用的人看到什么、点了会发生什么、什么情况不会发生。样式细节见 `docs/rounds/r004-room-extras/design.md` §8；接口与函数见 `docs/02-modules/r004-room-extras.md`。

## F-18 群聊（讨论）

| 项 | 行为 |
| --- | --- |
| 入口 | 抽屉「**讨论**」tab（默认页签）+ 输入框；抽屉按钮上带未读数字徽标 |
| 发送 | 回车发送、Shift+回车换行；上限 500 字；右下角实时计数；发送中气泡先出现（本地态），成功后替换为服务端返回的消息 |
| 失败 | 气泡标红并出现「重发」；**不吞输入**（草稿留在列表里） |
| 实时 | 房内广播（`lg.chat`）→ 另一端 1 秒内出现；多人同时发按时间排序 |
| 历史 | 进房/重连自动拉最近 50 条；「加载更早的消息」按 `before` 游标翻页 |
| 一致 | **库是唯一真相**：刷新/重进后与库一致（实测 3 条对 3 条，内容逐字相同） |
| 不做 | 编辑/撤回/删除、@提醒、图片与文件、私聊、跨页未读持久化 |

## F-19 举手

| 项 | 行为 |
| --- | --- |
| 入口 | 控制坞左组「**举手**」按钮（与麦克风/摄像头并列） |
| 自己 | 点一下举手（按钮变「放下手」并高亮 + 一次性脉冲），再点放下；重复点不会出现两条 |
| 管理 | 抽屉「讨论」tab 顶部出现「正在举手：A、B」；房主/协管可点「放下 A」替他人放下 |
| 实时 | 落库 + 广播全量快照（`lg.hands`，按 `at` 收敛）→ 两端一致 |
| 恢复 | 刷新/重进后举手状态从库恢复（`refresh()`）；房间结束时全部自动放下（`lowered_reason=room_ended`） |
| 不做 | 举手顺序队列/自动放行、举手的历史审计界面 |

## F-20 焦点发言

| 项 | 行为 |
| --- | --- |
| 入口 | 抽屉「成员」tab 的成员行「**给焦点**」（房主/协管可见）；已成焦点时按钮变「取消焦点」 |
| 效果 | **两端同时**把焦点格切到该成员（这是「服务端同步的唯一焦点」，不是各自视角） |
| 徽标 | 焦点格左上角「焦点 · 名称」；自己成为焦点时写「焦点 · 你」 |
| 全局指示 | 状态条显示「焦点 名称」（抽屉收起时唯一能看到的地方；徽标会被共享顶掉） |
| 边界 | 焦点对象**不再是成员**（离开/被移出）→ 焦点自动失效回落，状态条提示「焦点已失效」3 秒；**在册但离线** → 保留焦点并显示其头像块 |
| 不做 | 自动轮播、双焦点、焦点历史的界面 |

## F-21 屏幕共享

| 项 | 行为 |
| --- | --- |
| 入口 | 控制坞左组「**共享屏幕**」（共享中变「停止共享」） |
| 效果 | 共享画面占据**焦点格**（16:9 letterbox）并带「共享 · 名称」徽标与 3px 上缘线；自己的共享在舞台右下角有「停止共享」 |
| 音频 | 只共享画面，**不共享系统音频**（防与麦克风互相回授） |
| 停止 | 自己停（按钮）；房主/协管在成员行点「请求停止共享」→ 对方客户端自己停并看到提示「房主请求你停止共享屏幕（已为你停止）」——**协作式**，不是服务端强停（强停方案待实测，见 design §6.2） |
| 不做 | 录制、共享音频、多人同时共享（一次只认一块共享轨，最后发布的生效） |

## F-22 焦点格的优先级

`共享 > 手动焦点 > 说话者 > 自己`（ADR-0014）。人话版：有人在共享就直接看共享；否则看房主点名的人；都没人管就看谁在说话；再不然看自己。**一个时刻只有一块焦点格**，其余人降到缩格条并降权（`saturate(0.65) brightness(0.88)`）。

## 按钮矩阵（谁能看到 / 能点什么）

| 位置 | 按钮 | 参与者 | 协管 | 房主 | 未进房 / 离线 |
| --- | --- | --- | --- | --- | --- |
| 控制坞左组 | 麦克风 / 摄像头 | ✅ | ✅ | ✅ | —（不在房内） |
| 控制坞左组 | 举手 / 放下手 | ✅ | ✅ | ✅ | — |
| 控制坞左组 | 共享屏幕 / 停止共享 | ✅ | ✅ | ✅ | — |
| 控制坞右组 | 离开 | ✅ | ✅ | ❌（房主是「结束房间」） | — |
| 控制坞右组 | 结束房间 | ❌ | ❌ | ✅（危险色 + 二次确认） | — |
| 抽屉「讨论」 | 输入框 / 发送 | ✅ | ✅ | ✅ | — |
| 抽屉「讨论」 | 放下 X（他人的举手） | ❌ | ✅ | ✅ | — |
| 抽屉「成员」 | 给焦点 / 取消焦点 | ❌ | ✅ | ✅ | — |
| 抽屉「成员」 | 请求停止共享 | ❌ | ✅ | ✅ | — |
| 抽屉「成员」 | 移出 / 设为协管 / 移交房主 | ❌ | 移出（仅参与者） | ✅ | — |

## 演示脚本（5 步，双浏览器）

1. **群聊**：B 在「讨论」里发「我先补充一句」→ A 端 1 秒内看到同一条；A 回一句 → B 端同款。
2. **举手**：B 点控制坞「举手」→ A 抽屉「讨论」顶部出现「正在举手：B」；A（房主）点「放下 B」→ B 的按钮回到「举手」。
3. **焦点**：A 切「成员」tab 点 B 的「给焦点」→ **两端**焦点格都变成 B，A 端徽标「焦点 · B」、B 端「焦点 · 你」，状态条显示「焦点 B」。
4. **共享**：B 点「共享屏幕」→ 共享画面取代焦点格 + 「共享 · B」徽标（此时手动焦点不丢，取消共享后自动回到 B）；B 再点「停止共享」恢复。
5. **刷新**：刷新 A 的页面 → 消息条数与内容与库一致、举手状态恢复、焦点仍在 B（或已被取消）。

## FQ（本轮已定口径）

| 编号 | 问题 | 结论 |
| --- | --- | --- |
| FQ-1 | 群聊常驻侧栏还是抽屉？ | 抽屉「讨论」tab（默认）+ 未读数字徽标；不做常驻第二栏（保专注感） |
| FQ-2 | 焦点是各自视角还是统一？ | **统一**（服务端同步），否则「两浏览器一致」的验收不成立 |
| FQ-3 | 共享与焦点谁优先？ | 共享优先；但手动焦点**不丢**，共享结束后自动回到焦点 |
| FQ-4 | 停他人共享是强停吗？ | 本轮是**协作式**（对面客户端自己停）；服务端强停待实测（design §6.2） |
| FQ-5 | 举手放下的措辞 | 「放下手」（自己）/「放下 X」（管理者替他人）——不用「取消举手」 |
