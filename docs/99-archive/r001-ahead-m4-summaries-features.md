## 1. 使用者与使用时机

| 使用者 | 时机 | 关心什么 |
| --- | --- | --- |
| 房主 | 讨论结束、点「结束房间」之后 | 有人把这次讨论整理成可归档的文字，别让我自己回忆 |
| 参与者 | 结束后回到房间详情页 | 这次讨论到底得出了什么结论、我答应做的事是什么 |
| 错过讨论的人 / 评审 | 事后翻房间 | 不看全量聊天记录也能理解讨论走向 |

设计取向：**纪要面向「没参加讨论的人也能读懂」**，不是聊天记录的缩写；宁短勿编造。

## 3. 功能详述

### F-S-01 结束房间后自动生成

- **触发者**：房主（他要结束房间，纪要对他而言是「结束」的一部分）。
- **时序（用户视角）**：点「结束房间」→ 确认 → 房间立刻变只读（这一步不等纪要）→ 纪要区块显示「正在生成讨论纪要…」→ 通常几秒内出现正文；若超过 90 秒仍未完成，区块给出提示与「重新生成」。
- **为什么不让纪要阻塞结束**：房间结束是用户的明确意图，不能被外部模型服务的可用性拖住；纪要失败也不影响房间已经结束、成员已被移出。
- **规则**：一个房间只有一份纪要（再次生成是覆盖，不产生第二份）；自动生成只在结束时触发一次。

### F-S-02 查看纪要

- **入口**：房间详情页「讨论纪要」区块（位于最近消息之后，作为页面的收尾区块）。
- **可见性**：与房间详情同级——能打开这个房间页的人都能看（访客也可），符合「错过讨论的人也能读」的取向。
- **展示内容**：
  - 正文（Markdown 风格排版：小节标题 + 列表 + 段落）；
  - 角标信息一行小字：`由 deepseek-chat 生成 · 摄入 42 条发言 / 3,180 字 · 更新于 09-17 14:06`（让读者知道纪要靠什么材料、什么时候生成）；
  - 房主/协管额外看到「重新生成」按钮。
- **未生成时**（房间仍在进行 / 生成失败后未重试）：区块显示当前状态，不显示空白框。

### F-S-03 手动生成 / 重新生成

- **入口**：纪要区块内的按钮（房主、协管可见）。
- **两种语义**：
  - 房间仍在进行中点「生成纪要」→ 生成**当前快照**，并提示「当前讨论仍在进行，生成的是此刻的快照」；
  - 已有纪要后点「重新生成」→ 二次确认「重新生成会覆盖当前纪要，确定吗？」→ 覆盖同一份（次数会被记录）。
- **权限**：房主与协管可生成/重试；普通成员只看不说；访客不可见按钮。不满足权限时接口返回「没有权限执行该操作」。

### F-S-04 生成中状态与等待体验

- **表现**：按钮变「生成中…」并禁用；区块顶部显示进度条（不确定进度）与文案「正在整理聊天记录…」；页面其他部分仍可操作（不锁全页）。
- **时限**：单次最坏约 90 秒（超时 30 秒 × 最多 3 次尝试）；超时后转为失败态并给出重试入口，不无限转圈。
- **离开页面**：生成在服务端进行，用户可离开再回来；回来后按最新状态显示。

### F-S-05 生成失败与重试

- **表现**：区块显示错误条，含**错误摘要**（如「调用模型超时」/「LLM 未配置」/「模型返回空内容」）+ 「重新生成」按钮；房间的其他内容不受影响。
- **重试**：点「重新生成」即重试；重试成功覆盖为 `ready` 并刷新时间与角标信息。
- **排查辅助**：错误摘要与房间 id 记在库里；命令行 `python -m app.cli.summarize <room_id>` 可在终端复现同样调用（演示与排查用）。

### F-S-06 无文字发言的房间

- 讨论只开了音视频、没打字就结束 → 仍生成纪要，正文如实写「本房间没有文字发言，纪要仅包含成员与主题信息」，并在「材料不足说明」小节说明「缺少文字材料，无法提炼观点」。角标显示 `摄入 0 条发言`。
- 理由：房间结束必须留下产物；用「无内容」冒充失败会让房主困惑。

### F-S-07 命令行生成

- 用途：演示时不必依赖页面、离线核对素材装配是否正确、失败时快速复现。
- 表现：打印材料装配摘要（参与者数、摄入条数/字符数、是否发生裁剪）→ 打印模型返回前 200 字 → 打印库中该行状态与正文字数。
- 附加开关：`--dry-run` 只装配不发请求（看"喂给模型的到底是什么"）；`--force` 覆盖已生成内容。

## 4. 界面设计（详情页「讨论纪要」区块）

未生成（房间仍在进行，房主/协管视角）：
```
┌ 讨论纪要 ──────────────────────────────┐
│ 房间结束后会自动生成一份讨论纪要。        │
│ 也可以现在生成当前快照。                  │
│                          [生成纪要]      │
└─────────────────────────────────────────┘
```

生成中：
```
┌ 讨论纪要 ──────────────────────────────┐
│ ▓▓▓▓▓▓▓░░░░░░░░░  正在整理聊天记录…      │
│ （最长约 90 秒，可以离开页面稍后回来）     │
└─────────────────────────────────────────┘
```

已生成：
```
┌ 讨论纪要 ──────────────  [重新生成] ────┐
│ ## 讨论主题与目标                        │
│ ...正文（Markdown 排版）                 │
│ 由 deepseek-chat 生成 · 摄入 42 条发言   │
│ / 3,180 字 · 更新于 09-17 14:06          │
└─────────────────────────────────────────┘
```

失败：
```
┌ 讨论纪要 ──────────────────────────────┐
│ ⚠ 纪要生成失败：调用模型超时              │
│ 房间与其他内容不受影响。        [重新生成] │
└─────────────────────────────────────────┘
```

排版规则：正文小节用二级标题（`##`）、要点用无序列表、发言人写成「David：…」；表格/代码块等复杂结构的 Markdown 降级为纯文本行显示（不显示原始符号、不破坏排版）。

## 5. 纪要内容规格（六小节）

| 小节 | 写什么 | 合格标准 | 材料不足时 |
| --- | --- | --- | --- |
| 讨论主题与目标 | 用一两句话复述这次要讨论什么 | 与房间主题/标题一致，不扩写 | 照房间信息写 |
| 讨论要点 | 3–8 条要点，每条尽量带发言人 | 每条都能在聊天记录里找到依据 | 写「材料不足」 |
| 分歧与未决 | 出现分歧或悬而未决的问题 | 区分「已有共识」与「仍在争论」 | 写「无」 |
| 形成的结论 | 明确达成的结论 | 只写真的达成的内容，不替讨论下结论 | 写「未形成明确结论」 |
| 行动项 | 谁、做什么（有则写） | 不臆造负责人与期限 | 写「无」 |
| 材料不足说明 | 材料为何不足以支撑某节 | 明确缺什么（如「无文字发言」） | 无不足时省略 |

**格式示例（虚构材料，仅示排版与粒度，不是真实讨论）**
```
## 讨论主题与目标
围绕「用数学刻画细胞的能量代谢」做入门式讨论，目标是确定第一周各自阅读的范围。

## 讨论要点
- Ada 认为应从质量作用定律入手，先建立可手算的最小模型。
- David 提出用米氏方程解释酶促反应的非线性，担心数学门槛偏高。
- 两人都同意先做一次手算练习再决定是否上计算工具。

## 分歧与未决
- 起点用「质量作用定律」还是「米氏方程」仍未有定论。

## 形成的结论
- 第一周各自看教材第 3 章，第二次讨论用手算例子对照两种写法。

## 行动项
- Ada：整理质量作用定律的最小例子（下次讨论前）。
- David：找出一个米氏方程的实验数据例子。

## 材料不足说明
- 聊天记录中未涉及时间安排，故未写具体讨论时间。
```

## 6. 提示文案表

| 场景 | 文案 |
| --- | --- |
| 自动生成中 | 正在生成讨论纪要… |
| 快照生成提示 | 当前讨论仍在进行，生成的是此刻的快照 |
| 生成成功 | 纪要已生成 |
| 生成失败 | 纪要生成失败：{原因摘要}，可点击「重新生成」 |
| 未配置模型 | 纪要生成失败：LLM 未配置，请检查服务端环境变量 |
| 覆盖确认 | 重新生成会覆盖当前纪要，确定吗？ |
| 无文字发言 | 本房间没有文字发言，纪要仅包含成员与主题信息 |
| 权限不足 | 没有权限执行该操作 |
| 未生成（成员/访客视角） | 讨论纪要将在此房间结束后生成 |

## 7. 边界与体验规则

| 情况 | 用户看到什么 |
| --- | --- |
| 房间未结束就生成 | 生成的是快照，区块顶部有小字「快照：生成于房间进行中」 |
| 连续点两次「重新生成」 | 第二次被忽略（按钮已禁用），不会生成两份 |
| 生成时用户刷新页面 | 区块继续显示「生成中」，完成后显示正文 |
| 房间无文字发言 | 仍为「已生成」，正文说明无材料（不是失败） |
| 模型输出异常（含代码块/表格） | 降级为纯文本行显示，不崩版 |
| 房间不存在 / 无此房间权限 | 与房间详情同一提示（404 语义），不单独暴露纪要接口差异 |
| 事后不再需要纪要 | 当前轮不提供删除（如需要记 M5） |

## 8. 端到端演示脚本（接房间脚本）

1. 房间结束后（房间功能页 §6 第 7 步），房主页面纪要区块出现「正在生成讨论纪要…」。
2. 几秒后出现正文六小节；角标显示模型名、摄入条数/字数与更新时间。
3. 房主点「重新生成」→ 确认弹窗 → 覆盖后角标时间更新（次数增加）。
4. 参与者浏览器刷新 → 看到同一份纪要（只读，无「重新生成」按钮）。
5. 演示失败路径：临时把 `LLM_API_KEY` 置空 → 重新生成 → 区块显示「LLM 未配置」错误与重试按钮 → 恢复 Key 后重试成功。
6. 可选离线路径：终端执行 `python -m app.cli.summarize <room_id> --dry-run`，展示喂给模型的材料装配结果。
