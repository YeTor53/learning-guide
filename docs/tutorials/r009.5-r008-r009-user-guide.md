## 1. 讨论纪要（房间结束后）

**场景**：一场讨论散了以后，想让系统把「聊了什么、有什么分歧、下一步做什么」整理成一篇。

1. 房主在控制坞点 **「结束房间」** → 弹出确认 → 再点和确认框里的「结束房间」。房间转为只读，所有人被移出（房主落地回首页房间列表）。
2. 回首页 → 列表上方筛选切到 **「已结束」** → 卡片上点 **「讨论纪要」** 进入纪要页（实测该卡片入口可见、可点，落在 `/rooms/<id>/summary`）。
3. 页面上点 **「生成讨论纪要」**。等待几秒（**r009.5 实测 9.1 秒**；r008 同期实测 6.0 秒 / 纪要正文 632 字——同机同模型，浮动来自网络与素材量）。
4. 生成完按钮变成 **「重新生成」**，再点会**覆盖同一份**（不是新建第二份）。

**会上写进纪要的东西**：房间主题 / 标题 / 简介、在册成员（角色与是否在场）、近期聊天与系统消息。**r010 起**还会带上语音转写文本（转写功能尚未实现，登记在 r010）。

**生成不出来时**：

| 你看到 | 含义 | 怎么办
| --- | --- | --- |
| 「还没有纪要」 | 这间房还没生成过 | 点「生成讨论纪要」 |
| 「本房间未配置纪要服务」一类提示 | 服务端没配 LLM 密钥（`LLM_API_KEY`） | 让部署的人配 `.env`（键名见 `.env.example`） |
| 生成失败、可重试 | 外部模型调用失败（限流 / 断网） | 再点一次；失败会留下 `failed` 记录与原因，不影响房间本身 |

**注意**：纪要**不会**在结束房间的瞬间自动生成（避免外部调用失败污染结束流程）——必须有人点一下。

## 2. 限时邀请（指定「现在就来」的人）

**场景**：你正在房里，想让某个人**马上**进来，不想走「申请 → 等批准」那套。

1. 房内打开抽屉 → 切到 **「邀请」** tab（只有房主 / 协管看得到这个 tab）。
2. 选**有效期**（30 秒 / 60 秒，上限 1 分钟）与**可用次数**（1 / 2 / 3 / 5 次），点 **「生成邀请码」**。
3. 生成后行内出现**6 位小写码**与 **「复制链接」** 按钮，右侧倒计时写着「**50 秒后过期 · 已用 1/5**」这类字样。复制出来的链接形如 `/join?code=xxxxxx`。
4. 对方打开链接 → 加入页**自动预填**该码 → 点「加入房间」→ **直接进房**（跳过等候室），成员数 +1。

**口径**（r008 定稿）：

- 有效期**最长 1 分钟**，上限单点可调（服务端 `INVITE_TTL_MAX_SECONDS`，改一个数）。
- 用码进房**仍然受 8 人上限**约束：满员时返回「房间已满」，邀请不能绕过。
- **已在房里的人**再点一次自己的链接**不会**出错（幂等，200），也不会重复计数。
- 过期 / 用完 / 乱码：明确报「邀请无效」，不会静默失败。
- 这是**通用入口**（谁拿到码谁可进）；面向好友的**定向邀请**仍是未开发的 r011 需求（登记在 roadmap §9）。

## 3. 焦点系统（谁该被放大）

**场景**：想让某一个人的画面成为全场最大，或想让大家把注意力交给你。

**规则一句话（r011 起）**：**共享 > 手动焦点（房主/协管指定，含举手→给焦点） > 自己**；**说话不再获得焦点**（只说不动画面，格子上有「正在发言」高亮）；谁拿到焦点，谁的格子按 **1.4 倍**视觉份量放大（r009 实测：3 人档焦点格 556×631、其余 396×631，面积份量 1.40×），其余人**均分铺满**整个区域。

| 你的身份 | 你按住的位置叫什么 | 点一下会发生什么 |
| --- | --- | --- |
| 房主 | **取得焦点** | 自己立刻拿到焦点（无需别人批准）；再点变成**退出焦点** |
| 协管 | **申请焦点** | 生成一条**待批申请**；房主（或另一位非本人的管理身份）批准后才成为焦点 |
| 参与者 | **举手** | 举手示意；管理看到你格子上出现闪烁描边与「给焦点 / 放下手」两个按钮 |
| 任何拿到焦点的人 | **退出焦点** | 焦点清空，大家回到均分铺满 |

**给一个人焦点（管理视角）**：他的格子举手闪烁时，格上角标点 **「给焦点」** → 焦点转移给他，**同时他的举手被自动放下**（实测：房主端焦点格 1 个、举手格 0 个；对方按钮变成「退出焦点」）。
只想让他别举了，就点 **「放下手」**（实测：举手格 1 → 0，对方按钮回到「举手」）。

**均分铺满的实测**：1/2/3/4/6/8 人六档，区域铺满率 **100.0% / 98.5% / 97.0% / 97.6% / 96.1% / 94.6%**，格子面积相对差 **≤0.6%**，无横向溢出（脚本 `verify-stage-geometry.mjs`）。
**动效**：布局变化时格子**平移让位**（过渡 **240ms** = 令牌 `--stage-move-ms`，新来的人还有 220ms 的淡入缩放），动画结束时**终点误差 0.0px**（不会"动画完再啪地跳一下"）；举手期间格边框以 **1.2s** 呼吸闪烁（令牌 `--hand-blink-ms`，系统开了"减少动效"时改为静态描边）。

## 4. 麦克风那三个小竖条（声波）

房内控制坞的麦克风按钮旁有三根小竖条，跟着你说话的**音量**起伏（用 LiveKit 的 `audioLevel`，不额外开网页音频权限）。

- **静音时**三条**不动**（电平恒 0）——这是预期行为，不是坏了。
- 竖条只反映**你自己**的麦克风，不显示别人。
- r009 只做到"接线 + 元素与 CSS 链路可用"；**数值序列**（到底能涨到多少、多少帧更新一次）本轮**未取证**（取证脚本按纪律不发布测试音源），登记到 r011 一并取数。

## 5. 常见疑问

| 问题 | 回答 |
| --- | --- |
| 我关了麦克风，还能看到别人的焦点/举手吗？ | 能，这些是房间级状态，与你的麦克风无关 |
| 房主能直接把自己放大吗？ | 能，「取得焦点」一次点击即可 |
| 两个人同时举手，点「给焦点」会给谁？ | 给**你点的那一格**的那个人；另一个人的举手还在，需要你单独处理 |
| 协管申请焦点，自己能批自己吗？ | 不能，会被后端拒绝（须由另一位管理身份批准） |
| 邀请码能重复用吗？ | 按生成时选的次数（1/2/3/5），用完即失效；已进房的人再点仍放行（幂等） |
