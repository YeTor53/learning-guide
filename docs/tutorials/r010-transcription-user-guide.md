本页讲 **r010 的语音转写**：识别由**房间侧的转写服务**完成（不是你本机上传音频），说的内容会落进「讨论」流与会后的纪要里。

## 1. 你会看到什么

| 位置 | 现象 |
| --- | --- |
| 进房时 | 顶部一条告知条：「本房间会把说的话转成文字……关掉麦克风即不参与转写」；点「知道了」收起（30 秒后也会自动收起） |
| 控制坞 | 一个**只读**状态：「转写：开启」/「转写：未开启」（判据是房内有没有转写服务在场；它不是按钮） |
| 抽屉「讨论」 | 你和他人的话变成**气泡**：麦克风小图标 + 说话人 + 文本 + 左侧色条；还有人正在说时，先出现淡色的「识别中…」，定稿后变成正式气泡 |
| 会后 | 房间列表点「讨论纪要」，生成时会**把转写一起交给纪要模型**（转写段落数与聊天/成员信息一起进素材） |

## 2. 怎么用（3 步）

1. 进房 → 看到告知条，点「知道了」；不想被转写就点「**关掉我的麦克风**」（或按 `M`）。
2. 正常说话（麦克风开着的人才会被转写）。
3. 打开抽屉「讨论」，看自己那句话变成气泡；会后去「讨论纪要」看它进了纪要。

## 3. 关掉 / 不参与

- **关掉自己的麦克风 = 不参与转写**（没有音频就没有识别）。控制坞的「转写」是**状态显示**，不是开关。
- 不做「只关掉转写但继续说话」——房间侧识别由服务统一完成，没有单端裁剪（如实说明）。
- **不保留录音**：只存文字，音频不在我们这边留盘。

## 4. 演示前要准备什么（重要）

转写靠一个**独立进程**（房间侧的转写服务）。演示流程：

```bat
agents.bat                       :: 起转写进程（先起它；窗口里能看到 registered worker）
dev.bat                          :: 起后端 + 前端
```

- 起好后**建房 → 立刻进房**；转写服务进房需要十几秒（本次实测 **13.4 秒**），在那之前控制坞显示「转写：未开启」是**正常**的，它会自己变成「开启」。
- **演示前先自己进一次房再退（预热）**：本机首次连接 LiveKit 偶发超时换区，实测最慢 **24.2 秒**才连上（之后的人 0~2 秒）；预热一次就不会在观众面前卡住。
- 进程会**自动重启**（脚本已带重启循环）：万一它退出了，等 3 秒会自动回来，控制坞随后显示「开启」。
- 想零配额联调/演示：`set AGENT_STT=fake && agents.bat`（识别结果是固定的桩文本，用来演示链路，不花额度）。

## 5. 常见疑问

| 问题 | 回答 |
| --- | --- |
| 「转写：未开启」是不好吗？ | 说明转写服务不在场：先看那个进程窗口是否还在跑；不在就 `agents.bat` 起一下，十几秒后变「开启」 |
| 为什么我说话只有我自己看到？ | 转写是**房间级**的，所有人都会看到同一条流；若别人看不到，检查他们的网络是否断过（重连后会自动补齐库里的记录） |
| 气泡里的时长有时不显示？ | 时长来自识别服务给出的段落起止时间；拿不到时就不显示（不显示假的 0:00） |
| 免费额度够用吗？ | 免费档每月含 1,000 分钟转写服务时长 + $2.50 识别额度（≈ 数十到数百分钟，视模型单价）；**演示控制在 3 人以内**即可，8 人满房会超过免费档的并发上限 |
| 我能看到别人以前说过的话吗？ | 能，刷新/重进后会从库里补齐（转写与聊天、系统消息合成同一条流） |
