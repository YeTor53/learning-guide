# 教程二：双浏览器演示（等候 → 讨论 → 治理 → 结束）

准备两个浏览器窗口（或一个正常 + 一个隐私窗口），分别登录 `host@example.com`（房主 A）与另一个账号（B）。

## 1. 演示脚本（九步）

| # | 谁 | 做什么 | 应该看到什么 |
| --- | --- | --- | --- |
| 1 | A | 列表页「创建房间」（上限填 2，方便演示满员） | **直接进入交流页**（不再经过详情页），状态条显示 `已连接` |
| 2 | B | 列表页找到房间 → 「申请加入」 | **直接落到等待室**：暖色卡片 + 三步时间线 + 「你已经在门口了，房主看到就会开门」 |
| 3 | A | 交流页状态条右侧「成员与管理」（此时带**数字徽标**） | 抽屉里「待处理申请 · 1」+ 申请人留言；状态条下方提示「门口有 1 位在等房主批准」 |
| 4 | A | 点「批准」 | B 的等待室转「房主同意了，正在把你送进去」→ **1.5 秒后自动进入交流页**（B 全程不点按钮） |
| 5 | A | 开摄像头（B 也开） | A 的画面在主格（上缘强调线），B 在右侧竖排缩格且**降饱和降亮**；有人说话时头像出现声波脉冲 |
| 6 | A | 抽屉里对 B 点「设为协管」→「取消协管」 | 角色徽标即时变化；「移交房主」在「更多」菜单里（不可逆动作不并排） |
| 7 | A | 抽屉里对 B 点「移出」 | 先弹**页内确认**；确认后 B 立刻断开（Cloud 上旧票同时作废），B 回列表页并可重新申请 |
| 8 | 第三个账号 C | 申请加入 | 屋子已满（上限 2）时：C 进等待室，取票时得到 `房间已满（上限 2 人）` → **自动回房间列表**；A 移出一人后再批准 C 即可进入 |
| 9 | A | **底部控制坞右侧**点「结束房间」→ 坞内二次确认 → 确认 → 回列表页查看 | 房间状态变「已结束」，列表页该卡片无动作（回看将由 M4 纪要页承接）；**A 自己也被断开并回到房间列表**；另一个浏览器立刻显示「房间已结束，仅可查看历史内容」 |

## 2. 三条链路的"证据点"（截图/日志留痕）

- **等候链路**：B 的 URL 从 `/rooms/:id/wait` 自动变成 `/rooms/:id/live`（无需点击）
- **治理链路**：所有治理动作都在**交流页抽屉**里完成（列表页与等待页没有治理入口）
- **容量链路**：`在场（不含自己）>= capacity` → 取票 409 `ROOM_FULL`；有人离场后同一人取票 200

## 3. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| B 一直停在等待室 | A 没批准 / A 的抽屉没打开 | A 打开抽屉看「待处理申请 · N」；也可以让 B 点「撤回申请」再申请一次 |
| B 获批后没自动进 | 等待室页面被关闭或标签页休眠 | 回到等待室刷新即可（5 秒轮询会重新发现已批准） |
| 交流页显示「已断开」 | 网络抖动；Cloud 上被 `RemoveParticipant` | 点提示条上的「重新连接」（重签 Token，**不复用旧票**） |
| 有人进不来且提示满员 | 座位口径 = **在场人数**（未入场不占座） | 让房里的人先点「离开房间」或由房主「移出」，空出座位再进 |
| 被移出后回不来 | 已不是成员 | 回列表页卡片「申请加入」→ 等房主批准（这是设计：踢人 + 拒绝再签发） |

## 4. 实测记录（2026-09-19，r003 `cp-r003-3` 真机）

本轮把「谁来结束房间」这件事重新落回交流页（原来唯一的入口随房间管理页一起被删掉了）。实测（本机 `localhost:5173` + 后端 `:8000`，房主 `host@example.com`，新建房间 `room_14c610ea328bce80`）：

| 步骤 | 实测结果 |
| --- | --- |
| 房主进房 | 状态条 `已连接`、`1 / 8 在房间`；控制坞右侧是**危险色「结束房间」**（文字色 `rgb(255,208,208)`、描边 `rgba(255,107,107,0.55)` = `--live-end-border`），**没有「离开」** |
| 点「结束房间」 | 坞内就地展开确认：「结束这个房间？所有人将被移出、需重新申请才能进；房间转为只读，历史仍可查。」+「结束房间」/「取消（Esc）」 |
| 按 `Esc` | 确认行消失、按钮回到「结束房间」；连接仍是 `已连接`（房间与连接都没动）——**取消是安全的** |
| 再点并确认 | 状态条转 `已断开` + 「房间已结束」，页面自动回到房间列表；列表「已结束」筛选下该卡片显示 `已结束`、`0/8`、**无任何动作按钮** |
| 另一个成员的票 | `POST /api/rooms/{id}/token` → **409 `ROOM_ENDED`**（旧票作废、重进不可能） |
| Cloud 侧 | 直接问 LiveKit `ListRooms` → 房间列表为空：`delete_room` 真的把房间删了（不是只改库） |
| 库里 | `rooms.status='ended'` 且 `ended_at` 非空；`room_members` 里房主 `inactive / room_ended` |
| 非房主视角 | 用 `part@example.com` 进另一间房：控制坞是**「离开」**（`title="离开房间（不绑定快捷键）"`），页面里没有「结束房间」 |
| 越权 | 非房主对活跃房间直接调 `POST /api/rooms/{id}/end` → **403 `FORBIDDEN`** |

> 一条如实说明：上面的「另一个成员被断开」用的是**接口与平台两级证据**（409 + LiveKit 房间已消失），不是第二个浏览器的肉眼版；双浏览器全流程仍在 roadmap §9 台账里等演示日一次性走完。

## 5. 只看不动的底线
