面向深度学习主题的多人音视频讨论室（作业题目 A）的**项目级规划**。本文件只定方向与验收点，不写实现细节（细节归 `docs/01-architecture/`、`docs/02-modules/`）；里程碑只定方向，不承诺日期。

## 1. 起点现状（2026-09-16 实测）

- **项目性质**：全新项目；作业两题中选**题目 A：Learning Guide 学习讨论室**。
- **交付形态**：可演示的迷你产品网站（完整前端 + 服务端 + SQL 设计 + 设计说明）；通过后会被追问实现细节、边界情况与取舍。
- **时间与人力**：单人；作业要求收到后 4 个自然日内提交，约 16 小时专注工作量。
- **本机环境实测**：
  - 可用：`node v22.19.0`、`npm 10.9.3`（registry 指向 npmmirror）、`git 2.51.0`。
  - 依赖包可取：`next 16.3.5`、`@livekit/components-react 2.9.24`、`livekit-client 2.22.3`、`livekit-server-sdk 2.19.0`。
  - **LiveKit 自建可行且不需要 Docker**：官方 `livekit-server v1.13.7` 发布物含 `livekit_1.13.7_windows_amd64.zip`（18.9 MB）。
  - Docker 路径代价高：本机无 Docker；WSL 无已安装发行版、Hyper-V 未启用（需补 WSL2/发行版 + 重启）；Docker Desktop 安装包已在 `G:\Downloads`。
  - 本机 Python/OpenSSL 读系统证书库报 `ASN1: NOT_ENOUGH_DATA`（本机证书库损坏），自动化脚本一律用不校验上下文；浏览器侧不受影响。
- **可复用资产**：无。题面明确不得直接使用 LiveKit Meet 默认页面，须基于 LiveKit SDK / Components 自行实现。
- **外部归宿与口径**：
  - 交付给 First Light Tech 评审；**提交形态 = 仅 zip**（不建远端仓库），命名 `AI管培生_陀梓皓_题目A_<日期>.zip`。
  - 必须声明所用 AI 工具与模型；使用开源模板须注明来源并说明自己新增与修改的部分。
  - 提交时注明所选题目与实际投入小时数。

## 2. 终局目的

一句话：**做一个能现场演示的学习主题讨论室** —— 用两个浏览器完整走通「注册 → 建房 → 等候室审批 → 音视频 / 屏幕共享 / 举手 / 焦点发言 / 群聊 → 服务端踢人 → 结束房间 → LLM 生成讨论纪要并在房间详情查看」，且全部数据落库、关键链路可用脚本复现。

成功标准（可观测，逐条可验证）：

1. 双浏览器演示路径全通：8 人上限拒绝并有明确提示、等候室审批、Host / Moderator / Participant 三种角色权限可复现。
2. LiveKit Token 由服务端签发；仓库与前端产物中检索不到 Secret（给出检索命令与结果）。
3. SQL schema + 初始化脚本一条命令可跑，至少含 `users`、`rooms`、`room_members`、`join_requests`、`chat_messages`、`session_summaries`，表间关系在设计说明中有说明。
4. 冒烟脚本一条命令跑通「创建用户 → 建房 → 签发 Token → 写聊天 → 生成纪要」并打印结果。
5. 设计说明覆盖：架构、权限矩阵、表结构、LiveKit 与两个自定义能力、等候室与踢人流程、纪要生成链路、失败与边界情况、安全、未完成项。

非目标（明确不做）：多租户与计费、移动端 App、生产级运维（K8s / 监控告警）、自研音视频传输、UI 设计体系（用现成组件库起量）、公网部署。

## 6. 风险与假设

- **自建 LiveKit 的落地点未实测**（最大技术风险）：Windows 原生二进制能否在本机起服务、浏览器经 `localhost` 能否建连音视频与屏幕共享，须在 M2 第一轮先用最小 demo 验证，验证不过则回退 LiveKit Cloud（ADR-0001 变更）。
- **复杂度集中**：屏幕共享 / 焦点发言 / 二者优先级规则是三处最容易出坑的实时状态，M3 先定规则再实现。
- **时间预算**：16 小时对「必做全项」偏紧；超时则优先保证 M1~M4 必做闭环可演示，M5 全砍。
- **LLM 纪要**：依赖外部 API 的可用性与限流，须设计降级（生成失败时可见错误 + 可重试，不阻塞房间结束）。
- **安全**：Secret 泄露是硬扣分项；`.env` 不入库 + 前端产物检索作为固定验证步骤。
