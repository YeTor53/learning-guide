## 1. 目的

把交流页从「能看能听能管」变成**能一起讨论**：发消息（还能落库、刷新不丢）、举手要发言、房主/协管把发言焦点交给某人、共享屏幕讲材料 —— 并且四者在**两个浏览器里表现一致**，规则（谁能做、谁盖谁）写进文档、演示与规则一致。

顺带（你 2026-09-19 批复 Q6=1 / Q7=2）：把上一轮的文档与实测欠账、以及两处已知界面缺陷在本轮内一并了结，避免它们跟着交付走。

## 2. 边界

**做（M3 → r004）**

1. **群聊**：房内实时收发 + 落库（`chat_messages`，r001 已建表）+ 按房间拉最近消息（分页）；刷新/重进后与库一致。
2. **举手**：举手 / 自己放下 / 房主·协管放下他人；状态**落库**并在房内实时同步；重进或刷新后由服务端快照恢复。
3. **焦点发言**：**服务端同步的唯一焦点**（房主/协管指定与取消），所有人看到同一个放大对象。
4. **屏幕共享**：控制坞左组第三颗按钮（r002 §4.8 已预留位置）+ 共享画面进焦点格 + 「正在共享 · 名称」徽标 + 自己的「停止共享」入口；**Host/协管可停他人共享**。
5. **优先级规则**：`共享 > 手动焦点 > 说话者 > 自己` —— 写进功能页与 ADR，演示与规则一致（M3 的验收点）。
6. **还债（Q6=1）**：`smoke.py` 补齐 r002 的四个步骤（取 Token 200 / 非成员 403 / 踢后 403 / 结束后 409）并加 r004 步骤；三处实测留痕补齐：**断网重连**、**重连后设备状态保持**、**`prefers-reduced-motion` 降级**（r002 遗留的未取证项）。
7. **界面缺陷两项（Q7=2）**：① 侧边栏在「视口宽 < 高」时的样式错误（r002 台账登记，未复现未归因 → 本轮先复现再修）② 首页筛选条落在首屏之外（现象已确认，采用候选修法 ①：筛选条上移到顶栏正下方，附 ADR）。
8. **r003 收官回填**：索引表 r003 行转 `closed`、需求单转 `closed`、roadmap §7 与 §9 回填（与 r002 那次同款，由本轮首个增量偿还）。

**不做**

- M4 的 LLM 纪要与「归档」（归档已有构思页 `docs/99-archive/r003-ahead-m4-ended-rooms-archive.md`，不在本轮）；
- M5 增量项（录制转写 / Compose / 管理后台 / 录屏 / 跨房间存在性 / 封禁名单 / `ended` 房间回看）；
- 邀请能力（`docs/99-archive/r002-ahead-invites.md`，仍 backlog）；
- 自建 WebSocket 服务（Q2 已选 LiveKit Data Channel 路线，不引新依赖、不改运行形态）；
- 消息的编辑/删除/撤回、@提醒、图片与文件、表情面板、私聊、未读计数的跨页持久化（M5 或不做）；
- 举手/焦点的历史审计 UI（数据留痕即可，界面只看当前态）。

## 7. 风险

| 风险 | 对策 |
| --- | --- |
| Data Channel 只能房内广播（我们的后端不在房间里）→ 有人掉线时错过消息 | 库是唯一真相：进房/刷新/重连后**必须**用 HTTP 拉一次最近 50 条；广播只做加速（去重按服务端 id） |
| 广播乱序/重复 | 快照类消息（举手/焦点）带时间戳，**后到覆盖先到**；消息类按 id 去重、按 `created_at` 排序 |
| 屏幕共享在无头浏览器无法演示 | 共享走**你真机**（我会给最短操作路径）；我只做接口与状态断言 + 你的截图留痕 |
| 服务端「强停他人共享」可能不被 LiveKit 支持 | design §6.3 标为**待实测**：不可行则降级为协作停止并在文档如实写明（若影响对外可见面则走 CR） |
| 举手表与焦点表影响 `end_room` 的原子性 | 连带动作放在同一个事务里（与 r001 的三件事同锁）；测试覆盖「结束时有活跃举手」 |
| 群聊破坏专注感 | 抽屉默认收起、消息不弹 toast、未读只用一个数字徽标（U1）；静默 30 秒界面退场不变 |
| 两处界面缺陷要动 r001 已验收面 | 都走「先复现→取证→最小改动→截图对比」；筛选条上移补 ADR |
