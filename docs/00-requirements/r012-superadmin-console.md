## 1. 三块范围（本轮做）

### A 超管用户（block A）
1. **独立身份**：`superadmin` 能进**任何房间**（含满员房），能行使**任一房间房主的全部管理动作**（踢人 / 改角色 / 移交房主 / 结束房间 / 看待批申请 / 发系统消息口径同房主），另有**跨房**管理能力（= block B 的管理后台）。
2. **隐身**：进房时不出现在成员列表、不占舞台/焦点格、不显示头像；对 LiveKit 其他参与者也不可见（技术口径见 design §2：`VideoGrants.hidden=True`，livekit-api 1.2.1 已实测存在该字段）。
3. **不计入人数**：超管在场不影响容量判定（在册数不因超管变化），也不占「最多 8 人」的音视频承载兜底。
4. **只在管理动作时留痕**：超管平时在房间聊天栏不留痕；只有执行管理动作时产生**系统消息**（署名口径见 Q3）。
5. **只能管理，不发布音视频**：超管的 Token **关掉发布权限**（不能开麦、不能开摄像头、不发 DataChannel）——音视频走 LiveKit 计费，为省额度，超管只做管理；「可以发言」按 Q4 批复 = 在**全服大屏（文字）**发言。原话见 §10.1。

### B 简单管理后台（block B）
三张**列表**：房间（含房主/人数/待批/纪要状态）、用户（邮箱/显示名/注册时间/最后活跃/房间数）、纪要（房间/状态/模型/字数/时间）；三个**动作**：结束房间、删除房间、生成/重生纪要；每个动作留**审计流水** + 房内系统消息（Q5/Q7）。

### C 全服大屏聊天（block C）
参数沿用 `redirect-01.md` §4，并按你 2026-09-20 的细化改为：**右侧可收起的侧栏面板**（编辑器 Copilot 式——不遮主内容、随时展开/收起；仍**不做独立投屏页**）；登录用户可看可发言、未登录只读；全量落库；每人限流；单条 **500 字**；实时通道走 **SSE**（`GET /api/events` 只推通知型事件，HTTP 落库仍是唯一真相），断线用短轮询兜底。

## 3. 界面口径卡（r012·七项必答）

- **用户群与目标**：演示场景下的学习者与评审方；超管用它演示「平台级管理」（能进任意房、能管全部房间），所有登录用户用它看全服大屏讨论。
- **风格基调**：沿用暗色编辑风（`docs/04-style/global-style.md` §2），一句话：**ink 分层底色 + 单一强调色（`--accent`）+ 细网格与噪点质感**；新增的两个界面（管理后台页、大屏聊天面板）是既有编辑风的**延伸**，不另起风格。
- **参考物（沿用既有体系，不引新参考物）**：
  | 来源 | 看哪一层 |
  | --- | --- |
  | 本仓既有页（`RoomsPage` 卡片墙 / 抽屉 `RoomSidePanel` 双 tab / 纪要页） | 布局节奏、表头与分隔线、空态写法 |
  | 编辑器类工具的右侧面板（Copilot 式侧栏） | **只借交互形态**：右侧可收起、不遮主内容、宽度只容消息流（不看其配色与图标） |
  | `docs/04-style/global-style.md` §3–§10 | 令牌、排版阶梯、图标、动效、文案与错误呈现 |
- **技术栈**：React 18 + Vite（既有），CSS 变量 + 既有像素级样式类，无新依赖。
- **动效范围**：要 ① 聊天面板新消息插入（180ms 淡入上移）② 管理表行 hover 边框提亮 ③ 删除/结束的**行内二次确认**展开（沿用 `live-dock-confirm` 写法）④ 大屏面板入场淡入 ⑤ **右侧面板展开/收起**（宽度 + 透明度，`--t-base`）；不要 页面切换转场、滚动视差、3D、骨架屏以外的加载动画。
- **令牌与图标**：沿用 `frontend/src/styles/global.css` 既有令牌（`--ink-* / --text* / --accent / --warn / --danger / --line* / --r-* / --s-* / --t-* / --ease`）；本轮新增的少量参数（面板宽度、消息行高、表格密度）**集中写在 `global.css` 的新参数区**（单点可调）。图标库 **Lucide（唯一）**，零 emoji。
- **硬条款**：单一图标库 开、零 emoji 开、界面文案禁内部词（轮次/里程碑/检查点/cp-NNN/作业/考核）开 —— **本轮是否改：否**（§10 Q10 可改）。

## 6. 风险与假设

1. **「在册」是权限地基**（redirect-01 §6 风险 1）：现实现用 `assert_room_role` / `repo.get_active_member` 判一切权限；超管旁路必须**一次改全**（design §2 给出「只改 `assert_room_role` + `assert_manager_role` 两个函数，所有调用点自动受益」的收敛做法），否则会出现「能进但看不到 / 部分动作 403」的半成品。
2. **隐身与 LiveKit 的耦合**：隐身靠 Token 的 `hidden`+`attributes`（已实测字段存在），**依赖 LiveKit 服务端按 hidden 过滤**——实现第一步就要用 2 浏览器实测这一条；若实测不生效，退路见 design §8（前端按 identity 名单过滤 + worker 按 attributes 跳过）。
3. **容量不变量表述**：超管不写 `room_members`，「在册 ≤ 容量」不变；但必须写进 ADR-0024，否则后续轮次会把它当成破坏了 r005 的不变量。
4. **SSE 进程内广播**：单进程内存态，进程重启丢订阅（前端靠重连 + 轮询兜底）；多 worker 部署会漏事件 → 登记为已知限制（与 r011 心跳同口径）。
5. **限流与刷屏**：限流落**库计数**（非纯内存），重启不放大额度；口径与数字待 Q13/design §4 确认。
6. **删除房间不可逆**：硬删除（Q16）会连带删掉该房的聊天/纪要/转写；审计流水**不 FK 到 rooms**，所以删房后流水仍在（例外：`target_id` 变成悬空字符串，需在文档写明）。
7. **演示库**：本轮**不**执行 `db_init --reset --seed`（沿用 r011 口径「开发结束后统一清」）；超管演示账号若取 Q15①，需在收工清单里登记「清理/重建时机」。
